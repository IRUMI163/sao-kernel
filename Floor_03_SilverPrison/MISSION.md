## 1. この階層で学ぶC言語の核心

### ① 文字配列 `char buf[N]` と 終端文字 `\0`
C言語における文字列は、`char` 型の要素がメモリ上に連続して並んだ配列です。
文字列の終わりを識別するために、必ず末尾に `\0` (ASCIIコード `0`) を配置しなければなりません。

```text
[ 'S' ][ 'A' ][ 'O' ][ '\0' ][ ? ][ ? ]
  0      1      2      3      4    5   (インデックス)
```

例えば `"SAO"` という3文字の文字列を格納するには、終端文字 `\0` の分の1バイトを含めて、最低でも **4バイト** の配列サイズが必要となります。

```c
char buf[4] = "SAO"; // OK: 'S', 'A', 'O', '\0' が格納される
char bad[3] = "SAO"; // 危険: '\0' が入らず、文字列として破壊される！
```

---

### ② バッファオーバーフロー（BOF）の脅威
確保したメモリ領域（バッファ）を超えてデータを書き込んでしまう現象を **バッファオーバーフロー** と呼びます。
古くから存在する危険な関数 `strcpy` や `strcat` は、コピー先のバッファサイズを検証しないため、容易にバッファオーバーフローを引き起こします。

```c
char dest[5];
strcpy(dest, "EVERYDAY HERO"); // 超危険！ destの範囲を超えてメモリを破壊する
```

バッファオーバーフローが発生すると、プログラムのクラッシュ（Segmentation Fault）を引き起こすだけでなく、悪意ある第三者によってメモリ構造が書き換えられ、任意のコードを実行される脆弱性につながります。

---

### ③ オフバイワンエラー（Off-by-One Error）
プログラマを悩ませる典型的なバグが、境界値を「1」だけ見誤る **オフバイワンエラー** です。

```c
char buf[10];
// 10文字コピーしてしまい、'\0' を書くスペースがなくなる例
for (int i = 0; i <= 10; i++) { // ループ回数が11回になってしまっている
    buf[i] = src[i];
}
```

特に「バッファサイズ `dest_size` に対して最大何文字コピーできるか？」を考える際、終端文字 `\0` のための1バイトを忘れると、容易にオフバイワンエラーが発生します。
最大コピー可能文字数は常に **`dest_size - 1` 文字** です。

---

### ④ 入力のサニタイズと防御的プログラミング
外部からの入力や関数の引数は、常に危険を孕んでいます。
関数を設計する際は、以下のチェック（サニタイズ）を徹底する **防御的プログラミング** が不可欠です。

1. **NULLポインタチェック**: `dest` や `src` が `NULL` でないか？
2. **バッファサイズチェック**: `dest_size` が `0` でないか？
3. **境界値の厳守**: コピー処理後、どのような場合でも必ず末尾に `\0` を付与する。

## 2. 現場で飛び交う業界用語辞典

- **バッファオーバーフロー (Buffer Overflow / BOF)**:
  準備したメモリ領域（バッファ）を超えてデータが書き込まれ、隣接するメモリ領域が破損するセキュリティ脆弱性。
- **オフバイワンエラー (Off-by-One Error)**:
  ループの反復回数や配列のインデックス計算で「1」だけズレてしまう計算ミス。配列の領域外アクセスを引き起こす主原因。
- **AddressSanitizer (ASan)**:
  コンパイラ（GCC/Clang）の強力なメモリ検証ツール。`-fsanitize=address` オプションをつけてビルドすることで、境界外アクセスやメモリリークをリアルタイムに検知・報告してくれる。
- **防御的プログラミング (Defensive Programming)**:
  「引数にNULLが渡されるかもしれない」「バッファサイズが足りないかもしれない」といった不測の事態や誤用をあらかじめ想定し、安全装置（ガード条件）を組み込む設計手法。

### 関数の詳細仕様

#### 1. `int safe_str_copy(char *dest, size_t dest_size, const char *src)`
文字列 `src` をバッファ `dest` へ安全にコピーします。

- **引数エラーチェック**:
  - `dest == NULL` または `src == NULL` または `dest_size == 0` の場合、直ちに `-1` を返します。
- **コピー動作**:
  - `src` から最大 `dest_size - 1` 文字を `dest` にコピーします。
  - **どのような場合でも、必ず `dest` の末尾（`dest[dest_size - 1]` または実際の文字数の直後）に `\0` を付与します。**
- **戻り値**:
  - 切り詰めが発生せずに完全にコピーできた場合: `0`
  - バッファサイズ不足により切り詰め（Truncation）が発生した場合: `1`
  - 引数エラー等の不整合が発生した場合: `-1`

---

#### 2. `int safe_path_join(char *dest, size_t dest_size, const char *dir, const char *file)`
ディレクトリパス `dir` とファイル名 `file` を、間に `/` を挟んで結合し `dest` に格納します。

- **引数エラーチェック**:
  - `dest == NULL` または `dir == NULL` または `file == NULL` または `dest_size == 0` の場合、直ちに `-1` を返します。
- **パス結合動作**:
  - `dir` の末尾にすでに `/` が存在する場合は `/` を重複させず、そのまま `file` を結合します（例: `"/usr/local/"` + `"bin"` ➔ `"/usr/local/bin"`）。
  - `dir` の末尾に `/` が存在しない場合は `/` を1つ挟んで結合します（例: `"/usr/local"` + `"bin"` ➔ `"/usr/local/bin"`）。
- **バッファオーバーフロー防御**:
  - 結合後の完全なパス（終端文字 `\0` を含む）が `dest_size` に収まらない場合は、`dest` を変更せず（またはコピーを中断し）直ちに `-1` を返します。
  - 成功した場合は必ず末尾に `\0` を付与し、`0` を返します。
