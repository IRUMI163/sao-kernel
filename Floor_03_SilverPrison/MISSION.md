## 🎴 【基本構文パターン (Pattern Example)】
迷ったらまずこの型を見よ。第3層で使う武器はこれだけだ。

```c
/* パターンA: 必須の防御壁（NULLチェック & サイズ0チェック） */
if (!dest || !src || dest_size == 0) {
    return -1; // 不正な引数を即座に弾く（防御的プログラミング）
}

/* パターンB: 文字列の長さを測る (strlen は \0 を含めない純粋な文字数) */
size_t src_len = strlen(src);

/* パターンC: メモリコピー (memcpy) と最後の '\0' 打ち */
memcpy(dest, src, コピーするバイト数);
dest[最後の位置] = '\0'; // どんな時も末尾に必ずヌル文字を打つ！
```

## 🔍 【エディタに開いているコードの1行ずつ完全解体新書】
`safe_str.c` と `safe_str.h` に書かれているコードを1文字残らず分解・解説する。

```c
#include <string.h>
#include "safe_str.h"
```
- **`#include <string.h>`**: 文字列の長さを測る `strlen` や、メモリを高速コピーする `memcpy` を使うための標準ヘッダ。
- **`#include "safe_str.h"`**: この関数の設計図（プロトタイプ宣言）が書かれた自作ヘッダ。

```c
int safe_str_copy(char *dest, size_t dest_size, const char *src)
```
- **`int`**: 関数の戻り値の型。成功時は `0`、切り詰め時は `1`、エラー時は `-1` を返す設計。
- **`char *dest`**: コピー先（宛先）の文字配列の先頭アドレス。
- **`size_t dest_size`**: コピー先のバッファが耐えられる「最大バイト数」。
  - `size_t`（サイズ・ティー）とは、「メモリのサイズを表すための符号なし（マイナスがない）整数型」だ。32bit/64bit環境に応じて最適な整数サイズになる。
- **`const char *src`**: コピー元（情報源）の文字列。
  - **`const`**（コンスト）は「この関数の中で中身を書き換えてはならない読み取り専用」であることをコンパイラに誓約する修飾子だ。

```c
    (void)dest;
    (void)dest_size;
    (void)src;
    return -1;
```
- **`(void)...;`**: コンパイラからの「引数を受け取ったのに一度も使っていません」という警告（`-Wunused-parameter`）を防ぐおまじない。実装を書き換えたら削除して構わない。

## 💡 【これが実際の開発でどう使えるか】
C言語やOSカーネルで最も有名な脆弱性が **バッファオーバーフロー（BOF）** だ。
かつてC言語標準ライブラリの `strcpy` や `strcat` は「コピー先のバッファサイズ」を受け取らなかったため、悪意あるユーザーが巨大な文字列を送信するとメモリを突き破り、管理権限が乗っ取られる事件が世界中で多発した。

今回君が実装する `safe_str_copy` や `safe_path_join` は、LinuxカーネルやGoogleのChromeブラウザ、ゲームエンジンなどでも必ず実装されている**「指定サイズを決して超えず、溢れたら安全に切り詰めて必ず `\0` で閉じる」防御的文字列操作関数の原点**である。

## 1. この階層で学ぶC言語の核心

### ① 文字配列 `char buf[N]` と 終端文字 `\0`
C言語における文字列は、`char` 型の要素がメモリ上に連続して並んだ配列です。
文字列の終わりを識別するために、必ず末尾に `\0` (ASCIIコード `0`) を配置しなければなりません。

```text
[ 'S' ][ 'A' ][ 'O' ][ '\0' ][ ? ][ ? ]
  0      1      2      3      4    5   (インデックス)
```

例えば `"SAO"` という3文字の文字列を格納するには、終端文字 `\0` の分の1バイトを含めて、最低でも **4バイト** の配列サイズが必要となります。

```c
char buf[4] = "SAO"; // OK: 'S', 'A', 'O', '\0' が格納される
char bad[3] = "SAO"; // 危険: '\0' が入らず、文字列として破壊される！
```

---

### ② バッファオーバーフロー（BOF）の脅威
確保したメモリ領域（バッファ）を超えてデータを書き込んでしまう現象を **バッファオーバーフロー** と呼びます。
危険な関数 `strcpy` はコピー先のバッファサイズを検証しないため、容易にバッファオーバーフローを引き起こします。

```c
char dest[5];
strcpy(dest, "EVERYDAY HERO"); // 超危険！ dest(5バイト)の範囲を超えてメモリを破壊する
```

---

### ③ オフバイワンエラー（Off-by-One Error）
プログラマを悩ませる典型的なバグが、境界値を「1」だけ見誤る **オフバイワンエラー** です。

```c
char buf[10];
// 10文字コピーしてしまい、'\0' を書くスペースがなくなる例
for (int i = 0; i <= 10; i++) { // ループ回数が11回になってしまっている
    buf[i] = src[i];
}
```

特に「バッファサイズ `dest_size` に対して最大何文字コピーできるか？」を考える際、終端文字 `\0` のための1バイトを忘れると、容易にオフバイワンエラーが発生します。
最大コピー可能文字数は常に **`dest_size - 1` 文字** です。

---

## ⚠️ 【初心者が絶対にハマる3大トラップ】

1. **トラップ1: `strlen(src)` は `\0` を数えない！**
   - `"hello"` の `strlen` は `5` です。しかしメモリには `\0` を含めて `6` バイト必要です。
   - `dest_size` と比較する時、「`src_len < dest_size`」であればそのまま入ります（例: `src_len=5` で `dest_size=6` なら収まる）。
2. **トラップ2: 添字は `0` から始まる！**
   - サイズ `dest_size` の配列の最後の要素は `dest[dest_size - 1]` です。
   - うっかり `dest[dest_size] = '\0'` と書くと、配列の1つ外側のメモリを破壊して即死します。
3. **トラップ3: 切り詰めた時に末尾のヌル文字を忘れる！**
   - コピーできる最大文字数は `dest_size - 1` 文字。
   - コピーした直後に `dest[dest_size - 1] = '\0';` を忘れると、`printf("%s")` した瞬間にゴミデータを読み込んで暴走します。

## 🎯 【ボス戦クリア目標＆ステップ・バイ・ステップ写経ガイド】

### 武器①: `safe_str_copy` の実装手順
```c
int safe_str_copy(char *dest, size_t dest_size, const char *src) {
    // ステップ1: 引数のバリデーション (NULLチェックとサイズ0チェック)
    if (!dest || !src || dest_size == 0) {
        return -1;
    }

    // ステップ2: コピー元文字列の長さを測る
    size_t src_len = strlen(src);

    // ステップ3: バッファに全部収まる場合 (src_len < dest_size)
    if (src_len < dest_size) {
        // '\0' も含めて丸ごと (src_len + 1) バイトをコピー
        memcpy(dest, src, src_len + 1);
        return 0; // 完全コピー成功
    } else {
        // ステップ4: バッファから溢れる場合 (切り詰め処理)
        // dest_size - 1 文字だけをコピーし、最後を必ず '\0' にする
        memcpy(dest, src, dest_size - 1);
        dest[dest_size - 1] = '\0';
        return 1; // 切り詰め発生を示す 1
    }
}
```

### 武器②: `safe_path_join` の実装手順
ディレクトリとファイル名を `/` で安全につなぐロジック。
```c
int safe_path_join(char *dest, size_t dest_size, const char *dir, const char *file) {
    // ステップ1: 引数のバリデーション
    if (!dest || !dir || !file || dest_size == 0) {
        return -1;
    }

    // ステップ2: 長さの計算
    size_t dir_len = strlen(dir);
    size_t file_len = strlen(file);

    // dir の末尾にすでに '/' があるか確認
    int has_slash = (dir_len > 0 && dir[dir_len - 1] == '/');

    // 必要な総バイト数: dir長 + (スラッシュが必要なら1, 不要なら0) + file長 + 終端ヌル文字(1)
    size_t needed = dir_len + (has_slash ? 0 : 1) + file_len + 1;
    if (needed > dest_size) {
        return -1; // バッファ不足！溢れさせる前に拒否する
    }

    // ステップ3: 安全に順番に詰めていく
    memcpy(dest, dir, dir_len);
    size_t pos = dir_len;
    if (!has_slash) {
        dest[pos++] = '/';
    }
    memcpy(dest + pos, file, file_len);
    pos += file_len;
    dest[pos] = '\0'; // 最後に必ずヌル文字！

    return 0;
}
```
