## 1. この階層で学ぶC言語の核心

これまでの階層では、単一の `.c` ファイル内にすべての処理（`main` 関数など）を記述してきました。
しかし、プログラムの規模が大きくなると、コードの視認性が著しく低下し、複数人での開発や共通処理の再利用が困難になります。
この層では、コードを機能ごとにファイル単位で分割・整理する「分割コンパイル」と「モジュール化」の手法を学びます。

---

### ① 関数分割とプロトタイプ宣言

処理のかたまりを独立した「関数」として切り出すことを**関数分割**と呼びます。
C言語では、コンパイラはコードを**上から下へ**順に読み進めます。そのため、ある関数 `A` の中で別の関数 `B` を呼び出す場合、原則として `B` の定義または宣言が `A` より前に存在しなければなりません。

```c
#include <stdio.h>

// プロトタイプ宣言（関数の「看板」を前に立てておく）
int calc_sum(int a, int b);

int main(void) {
    int total = calc_sum(10, 20); // コンパイラは関数の型と引数を知っているためOK
    printf("Total: %d\n", total);
    return 0;
}

// 関数の実体（本体）の定義
int calc_sum(int a, int b) {
    return a + b;
}
```

#### プロトタイプ宣言とは？
関数の名前、戻り値の型、引数の型・個数だけをコンパイラに事前に知らせる宣言です。
プロトタイプ宣言があることで、関数の実体がコードの下部や**別のファイル**にあっても、コンパイラは型チェックを正しく行うことができます。

### ② ヘッダファイル（`.h`）と `#include`

別の `.c` ファイルで定義された関数を呼び出したい場合、呼び出し側でその関数のプロトタイプ宣言が必要になります。
しかし、利用する側のファイルごとに毎回手動でプロトタイプ宣言を書くのは非効率的でミスのもとです。

そこで用いられるのが**ヘッダファイル（`.h`）**です。

- **`calc.h`** : プロトタイプ宣言や定数定義、構造体宣言を記述する。
- **`calc.c`** : `calc.h` で宣言された関数の「実際の処理（定義）」を記述する。
- **`main.c`** : `#include "calc.h"` を書き、宣言された関数を利用する。

#### `#include <...>` と `#include "..."` の違い
| 形式 | 検索対象ディレクトリ | 主な用途 |
| :--- | :--- | :--- |
| `#include <stdio.h>` | システムの標準ライブラリディレクトリ | `stdio.h`, `stdlib.h`, `string.h` 等 |
| `#include "calc.h"` | カレントディレクトリ（自作ファイルの場所） | 開発者が自作したヘッダファイル |

---

### ③ インクルードガード（`#ifndef`）の絶対的役割

複数のファイルから同じヘッダファイルが間接的にインクルードされると、同一のプロトタイプ宣言や型定義が多重に読み込まれ、**多重定義エラー（Redefinition error）**が発生します。

これを防止するための必須構造が**インクルードガード**です。

```c
#ifndef CALC_H
#define CALC_H

// ここにプロトタイプ宣言などを記述する
int calc_storage_percent(long used, long total);
int calc_player_rank(int score);

#endif /* CALC_H */
```

#### 動作の仕組み
1. 初めて `calc.h` が読み込まれたとき、マクロ `CALC_H` は未定義です（`#ifndef CALC_H` が真）。
2. 直後の `#define CALC_H` により `CALC_H` が定義され、中身が処理されます。
3. 同じビルド単位で2回目以降に `calc.h` が読み込まれると、`CALC_H` は既に定義されているため、`#ifndef CALC_H` から `#endif` までの内容がすべてスキップされます。

### ④ 分割コンパイルの仕組み

C言語では、複数の `.c` ファイルを個別にコンパイルしてオブジェクトファイル（`.o`）を作成し、最後にそれらを結合して1つの実行ファイル（バイナリ）を生成します。

```bash
# 1. 各ソースファイルを個別コンパイル（-c オプションでオブジェクトファイル生成）
gcc -std=c11 -Wall -Wextra -Werror -c main.c -o main.o
gcc -std=c11 -Wall -Wextra -Werror -c calc.c -o calc.o

# 2. オブジェクトファイルをリンクして実行ファイルを生成
gcc main.o calc.o -o floor_runner
```

### ⑤ `Makefile` の書き方とビルド自動化

ソースファイルの数が増えると、手動で `gcc` コマンドを何度も打つのは困難になります。
ビルド手順を自動化するツールが `make` であり、その設定ファイルが `Makefile` です。

#### 構文規則
```makefile
ターゲット: 依存ファイル1 依存ファイル2
	実行するコマンド（※行頭は必ず「TAB文字」でインデントする）
```

#### 代表的な `Makefile` 例
```makefile
CC = gcc
CFLAGS = -std=c11 -Wall -Wextra -Werror

# デフォルトターゲット
all: floor_runner

# 最終バイナリの生成（リンカ）
floor_runner: main.o calc.o
	$(CC) $(CFLAGS) -o floor_runner main.o calc.o

# 各オブジェクトファイルの生成（コンパイル）
main.o: main.c calc.h
	$(CC) $(CFLAGS) -c main.c -o main.o

calc.o: calc.c calc.h
	$(CC) $(CFLAGS) -c calc.c -o calc.o

# クリーンアップルール
clean:
	rm -f *.o floor_runner
```

## 2. 現場で飛び交う業界用語辞典

- **リファクタリング（Refactoring）**:
  プログラムの外部から見た挙動（出力結果）を変えることなく、内部のコード構造を整理・改善する作業のこと。関数の分割や重複コードの除去が含まれる。
- **モジュール化（Modularization）**:
  大規模なシステムを機能ごとに独立した部品（モジュール）に切り分けること。保守性、再利用性、テスト容易性が飛躍的に向上する。
- **リンカ（Linker）**:
  コンパイルによって生成された複数のオブジェクトファイル（`.o`）やライブラリを結合し、1つの実行可能ファイル（バイナリ）を作成するプログラムのこと。関数の呼び出し元と呼び出し先のนี่アドレスを結びつける（リンクする）。

## 3. ボス戦ミッション（実装仕様）

この階層では、計算モジュール `calc` の設計・分割を行います。

### 担当ファイル構造
- `calc.h` : 受講者用ヘッダファイル。インクルードガードとプロトタイプ宣言が欠落している（`/* TODO */` を補完すること）。
- `calc.c` : 受講者用実装ファイル。関数内部が未完成（`/* TODO */` を補完すること）。
- `main.c` : 完成済みエントリポイント（編集不要）。
- `Makefile` : 受講者用ビルド定義。ターゲット `floor_runner` のルールが未完成（`/* TODO */` を補完すること）。

### 実装要求（`calc.c` / `calc.h`）

1. **`int calc_storage_percent(long used, long total)`**
   - 使用量 `used` と 総容量 `total` から使用率（パーセンテージ: 0〜100）を計算して `int` 型で返す。
   - `total <= 0` の場合は異常値として `-1` を返す。
   - 小数点は切り捨て（整数除算 `(used * 100) / total`）。

2. **`int calc_player_rank(int score)`**
   - プレイヤーのスコアに応じたランク（整数値）を返す。
   - `score >= 1000` ➔ ランク `3` (Sランク)
   - `score >= 500`  ➔ ランク `2` (Aランク)
   - `score >= 100`  ➔ ランク `1` (Bランク)
   - `score < 100`   ➔ ランク `0` (Cランク)

### 要求される出力フォーマット（`main.c` 実行時）
`main.c` が `calc.h` を読み込んで正しくビルド・実行された場合、以下のフォーマットが出力される。

```text
==================================================
  [AINCRAD SYSTEM] : DRAFTING ROOM MODULE
==================================================
STORAGE USAGE : 42%
PLAYER SCORE  : 750 (RANK: 2)
==================================================
```

### クリア手順（ターミナルで実行）
1. 手動で `make` を実行してコンパイルとテストを行う場合：
   ```bash
   make
   ./floor_runner
   ```
2. ボス戦（自動採点スクリプト）に挑む場合：
   ```bash
   ./test.sh
   ```
   緑色の文字で `【判定】 CLEARED!` と表示されれば第4層突破だ！
