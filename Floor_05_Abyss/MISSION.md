## 🎴 【基本構文パターン (Pattern Example)】
迷ったらまずこの型を見よ。第5層で使う武器はこれだけだ。

```c
/* パターンA: ポインタ渡し（実体を直接書き換えてもらう） */
void level_up(int *level) {
    if (level != NULL) {
        (*level)++; // カッコで囲んでから ++ するのが鉄則！
    }
}
// 呼び出し側: アドレス演算子 & を付けて住所を渡す
level_up(&current_level);

/* パターンB: NULLポインタガード（触る前に必ず確認） */
int safe_read_hp(const int *hp_ptr) {
    if (hp_ptr == NULL) {
        return -1; // 0番地を触ると即死するため、事前に退避
    }
    return *hp_ptr; // 住所の先にある中身を取り出す
}

/* パターンC: 配列の安全ループ（< size を厳守） */
for (int i = 0; i < size; i++) {
    arr[i] = (i + 1) * 10; // 0 から size - 1 まで正確に巡回
}
```

## 🔍 【エディタに開いているコードの1行ずつ完全解体新書】
`main.c` に書かれているポインタコードを1文字残らず分解・解説する。

### 1. `void level_up(int *level)`
- **`int *level`**: 「`int` 型のデータが入っているメモリの番地（アドレス）」を受け取るためのポインタ型引数。
- **`(*level)++`**: 
  - `*level` で「番地の先にある中身（現在のレベル数値）」を取り出す。
  - カッコ `()` で囲む理由: `*level++` と書くと、C言語の優先順位により「番地そのものを進めてしまう」という致命的なバグになる。中身を1増やしたい時は必ず `(*level)++` と書く。
- **呼び出し側 `level_up(&current_level);`**:
  - `&` は「アドレス演算子」。`current_level` という変数がメモリ上の何号室にあるか（例: `0x7ffee...`）を調べて関数に渡す。

### 2. `int safe_read_hp(const int *hp_ptr)`
- **`const int *hp_ptr`**:
  - `const`（読み取り専用）が付いているため、「HPの数値を読むことはできるが、書き換えることは禁止」という安全誓約。
- **`if (hp_ptr == NULL)`**:
  - `NULL` とは「どのメモリも指していない空っぽ（0番地）」のこと。
  - コンピュータでは0番地を読み書きしようとした瞬間に、OSの防御システムが発動してプログラムが即座に強制終了（クラッシュ）させられる。これを未然に防ぐのが `NULL` ガードだ。

### 3. `void init_array(int *arr, int size)`
- **`for (int i = 0; i < size; i++)`**:
  - サイズ `size` の配列の有効な部屋番号は `0` から `size - 1` まで。
  - `i <= size` にしてしまうと、配列の外側の未知のメモリを上書きしてしまい、システムを破壊する（Off-by-One エラー）。

## 💡 【これが実際の開発でどう使えるか】
「なぜわざわざポインタなんてややこしいものを使うのか？」初心者は必ずそう疑問に思う。
その理由は2つある：

1. **実体を直接書き換えるため**:
   C言語の関数は基本的に戻り値を1つしか返せない。だが、ポインタ渡しを使えば「関数の引数に渡した複数の変数」を同時に更新させることができる。
2. **圧倒的なパフォーマンス（巨大データの高速受け渡し）**:
   数ギガバイトある3Dグラフィックモデルや巨大なプレイヤーデータを関数に渡す際、値渡し（コピー）をするとメモリを食い尽くし、ゲームが一瞬フリーズする。
   だがポインタを使えば、データのサイズに関わらず「たった8バイトの住所」を1つ渡すだけで済む。これがOSやゲームがC言語で書かれる最大の理由である。

## 1. この階層で学ぶC言語の核心

### ① メモリ空間とアドレス演算子 `&`・間接参照演算子 `*`
コンピュータのメモリ（RAM）は、1バイトごとに固有の「番地（アドレス）」が割り当てられた巨大なロッカーのようなものです。

```text
+-------------------+-------------------+-------------------+
| メモリ番地        | 変数名            | 値                |
+-------------------+-------------------+-------------------+
| 0x7ffd5f81a02c    | level             | 10                |
| 0x7ffd5f81a030    | ptr               | 0x7ffd5f81a02c    |
+-------------------+-------------------+-------------------+
```

- **アドレス演算子 `&`**: 変数が配置されているメモリの番地を取得します。
  `&level` は 「`level` 変数が置かれているメモリ番地」を表します。
- **ポインタ変数**: メモリ番地（アドレス）を記憶するための専用変数です。
  `int *ptr = &level;` は 「`int` 型の番地を格納する変数 `ptr` に `level` の番地を代入する」という意味になります。
- **間接参照演算子（デファレンス） `*`**: ポインタが指し示している番地の「中身」を読み書きします。
  `*ptr = 20;` と書くと、`ptr` が指す番地（`level` の領域）の値が `20` に書き換わります。

---

### ② 値渡し vs ポインタ渡し

#### 【危険】値渡しの罠（原本が変わらない）
```c
void level_up_bad(int level) {
    level++; // コピーされた変数を増やしているだけ！
}
```

#### 【解決】ポインタ渡し（原本を直接更新）
```c
void level_up_good(int *level_ptr) {
    if (level_ptr != NULL) {
        (*level_ptr)++; // 指し示している先の実体を直接インクリメント
    }
}
```

## ⚠️ 【初心者が絶対にハマる3大トラップ】

1. **トラップ1: `*level++` と書いてしまう！**
   - `*level++` は「ポインタのアドレスを次の部屋に進める」という意味になってしまいます。
   - 中身の数値を増やしたい時は、必ずカッコをつけて `(*level)++` と書いてください。
2. **トラップ2: 呼び出し側で `&` を付け忘れる！**
   - 引数が `int *level` の関数には、変数の実体 `current_level` ではなく、住所 `&current_level` を渡す必要があります。
3. **トラップ3: `i <= size` による境界オーバー（Off-by-One）！**
   - 配列 `int buffer[5]` の有効な添字は `0, 1, 2, 3, 4` です。
   - `i <= 5` までループを回すと、存在しない 5 番目の部屋を書き換えてしまい、ASanに即座に討伐されます。
