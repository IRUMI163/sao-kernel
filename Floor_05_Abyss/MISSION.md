## 1. この階層で学ぶC言語の核心

### ① メモリ空間とアドレス演算子 `&`・間接参照演算子 `*`
コンピュータのメモリ（RAM）は、1バイトごとに固有の「番地（アドレス）」が割り当てられた巨大なロッカーのようなものです。

```text
+-------------------+-------------------+-------------------+
| メモリ番地        | 変数名            | 値                |
+-------------------+-------------------+-------------------+
| 0x7ffd5f81a02c    | level             | 10                |
| 0x7ffd5f81a030    | ptr               | 0x7ffd5f81a02c    |
+-------------------+-------------------+-------------------+
```

- **アドレス演算子 `&`**: 変数が配置されているメモリの番地を取得します。
  `&level` は 「`level` 変数が置かれているメモリ番地」を表します。
- **ポインタ変数**: メモリ番地（アドレス）を記憶するための専用変数です。
  `int *ptr = &level;` は 「`int` 型の番地を格納する変数 `ptr` に `level` の番地を代入する」という意味になります。
- **間接参照演算子（デファレンス） `*`**: ポインタが指し示している番地の「中身」を読み書きします。
  `*ptr = 20;` と書くと、`ptr` が指す番地（`level` の領域）の値が `20` に書き換わります。

```c
int level = 10;
int *ptr = &level; // ptr に level のアドレスを格納

printf("levelの値: %d\n", level);     // 10
printf("levelの番地: %p\n", (void*)&level); // 0x7ffd5f81a02c
printf("ptrの保持する値: %p\n", (void*)ptr); // 0x7ffd5f81a02c
printf("*ptrの指す値: %d\n", *ptr);   // 10

*ptr = 20; // ptrを経由してlevelを直接書き換える！
printf("変更後のlevel: %d\n", level); // 20
```

### ② 値渡し（Pass by Value）vs ポインタ渡し（Pass by Pointer）
C言語の関数引数は、デフォルトではすべて**値渡し（コピー）**です。

#### 【危険】値渡しの罠
```c
void level_up_bad(int level) {
    level++; // 引数としてコピーされたローカル変数 level を増やしているだけ！
}

int main(void) {
    int my_level = 10;
    level_up_bad(my_level);
    // my_level は 10 のまま！呼び出し元の値は変化しない！
    return 0;
}
```

```text
[main のスタック領域]          [level_up_bad のスタック領域]
+--------------------+        +--------------------+
| my_level: 10       | --コピー->| level: 10         |
+--------------------+        +--------------------+
  (変化なし!)                    (11 に増やすが関数終了で消滅)
```

#### 【解決】ポインタ渡し
呼び出し元の変数の「番地」を関数に渡すことで、関数の中から呼び出し元の実体を直接書き換えることができます。

```c
void level_up_good(int *level_ptr) {
    if (level_ptr != NULL) {
        (*level_ptr)++; // 指し示している先の実体を直接インクリメント
    }
}

int main(void) {
    int my_level = 10;
    level_up_good(&my_level); // アドレスを渡す
    // my_level は 11 に更新される！
    return 0;
}
```

```text
[main のスタック領域]          [level_up_good のスタック領域]
+--------------------+        +--------------------+
| my_level: 10 <=====|========| level_ptr: 0x...02c| (my_levelの番地を保持)
+--------------------+        +--------------------+
  (*level_ptr)++ により 11 に直接書き換わる！
```

### ③ NULLポインタとセグメンテーション違反（SIGSEGV）
ポインタがどこも指していない状態を表す特別な値が `NULL`（通常はアドレス `0`）です。

存在しない無効なアドレス（`NULL` や解放済み領域、許可されていない領域）にアクセス（間接参照 `*`）しようとすると、OSのメモリ保護機能によりプログラムは即座に強制終了します。これが**セグメンテーション違反（Segmentation Fault / SIGSEGV）**です。

```c
int *ptr = NULL;
*ptr = 100; // 💥 CRASH! セグメンテーション違反が発生！
```

#### 防御的プログラミング：NULLチェックの徹底
ポインタを引数として受ける関数では、間接参照する前に必ず `NULL` チェックを行うのが鉄則です。

```c
int safe_read_hp(const int *hp_ptr) {
    // ポインタが NULL でないか必ず確認する
    if (hp_ptr == NULL) {
        return -1; // エラー状態を示す値を返す
    }
    return *hp_ptr;
}
```

### ④ メモリ境界外アクセス（Off-by-One error / バッファオーバーフロー）
配列の要素数が `N` の場合、有効なインデックスは `0` から `N - 1` までです。
ループ条件を `i <= N` と誤ってしまうと、配列の外側のメモリ（`N` 番目の領域）にアクセスしてしまいます。

```text
配列 arr[5] のメモリ配置 (size = 5)
+----------+----------+----------+----------+----------+------------------+
| arr[0]   | arr[1]   | arr[2]   | arr[3]   | arr[4]   | 🚨 arr[5] (侵犯!) |
+----------+----------+----------+----------+----------+------------------+
  有効インデックス: 0, 1, 2, 3, 4                         境界外アクセス！
```

### ⑤ AddressSanitizer（ASan）によるデバッグとログの読み方
コンパイル時に `-fsanitize=address -g` フラグを付与すると、LLVM/GCC の AddressSanitizer (ASan) が有効化され、メモリ違反が発生した瞬間に詳細なエラーログを出力してくれます。

#### ASan ログの解読ガイド

```text
=================================================================
==12345==ERROR: AddressSanitizer: global-buffer-overflow on address 0x...
READ of size 4 at 0x... thread T0
    #0 0x... in init_array /path/to/main.c:25
    #1 0x... in main /path/to/main.c:45

0x... is located 0 bytes to the right of global variable 'arr' defined in 'main.c:10'
SUMMARY: AddressSanitizer: global-buffer-overflow /path/to/main.c:25 in init_array
=================================================================
```

1. **エラー種別 (`ERROR: AddressSanitizer: ...`)**:
   - `global-buffer-overflow` / `stack-buffer-overflow`: 配列等の境界外アクセス。
   - `SEGV on unknown address`: NULLポインタや不正アドレス参照。
2. **発生箇所 (`#0 0x... in function /path/to/file.c:line`)**:
   エラーが発生した関数名と行番号（上記なら `main.c` の 25 行目）。
3. **詳細説明 (`is located ... bytes to the right of...`)**:
   変数の境界から何バイトオーバーしたかを表示。

## 2. 現場で飛び交う業界用語辞典

- **ポインタ（Pointer）**:
  メモリ上のアドレス（番地）を保持する変数。C言語において最も強力であり、最もバグを生み出しやすい要素。
- **デファレンス（Dereference / 間接参照）**:
  ポインタ変数に `*` を付けて、そのポインタが指し示しているアドレスに格納されているデータにアクセスすること。
- **SIGSEGV（Segmentation Fault / セグフォ）**:
  アクセス権限のないメモリ領域を読み書きしようとした時に、OSから送られるシグナル（シグナル番号11）。
- **Off-by-One エラー**:
  ループの境界条件を「1」間違えることで発生するバグ（`<` を `<=` と書く、`0` 開始か `1` 開始かを勘違いするなど）。
- **AddressSanitizer（ASan）**:
  Googleが開発した高速メモリバグ検出ツール。コンパイルオプション `-fsanitize=address` を付けるだけで利用可能。

## 3. ボス戦ミッション（中間試験仕様）

この階層の `main.c` には、呪われた3つのバグが仕込まれている。
これらのバグをすべて解読・修正し、システムチェックを通過させよ。

### 修正対象の3つの関数

1. **`void level_up(int level)`**:
   - **バグ**: 値渡しになっているため、呼び出し元（`main` 関数内）のレベル変数が上がらない。
   - **修正仕様**: 引数をポインタ渡し `int *level` に変更し、ポインタ経由で加算すること。
2. **`int safe_read_hp(const int *hp_ptr)`**:
   - **バグ**: `NULL` が渡された時にチェックせず `*hp_ptr` を参照するため、セグメンテーション違反でクラッシュする。
   - **修正仕様**: `hp_ptr == NULL` の場合は `*hp_ptr` を参照せず、安全に `-1` を返す処理（`NULL` ガード）を追加すること。
3. **`void init_array(int *arr, int size)`**:
   - **バグ**: ループ条件が `i <= size` になっており、Off-by-One によるバッファオーバーフローが発生して ASan に検知される。
   - **修正仕様**: ループ条件を `i < size` に修正すること。
