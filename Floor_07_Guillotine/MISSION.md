## 1. この階層で学ぶC言語の核心

### ① スタック領域（Stack）とヒープ領域（Heap）の決定的な違い

C言語が扱うメモリ空間は、主に**スタック領域**と**ヒープ領域**の2つに大別されます。

| 比較項目 | スタック領域 (Stack) | ヒープ領域 (Heap) |
| :--- | :--- | :--- |
| **管理主体** | コンパイラ / OS（自動管理） | プログラマ（手動管理） |
| **サイズ決め** | コンパイル時にサイズが決定 | プログラム実行時に動的に決定 |
| **メモリサイズ** | 小さい（数MB程度、上限あり） | 巨大（利用可能RAMの全域） |
| **ライフサイクル** | スコープ（関数）を抜けると自動消滅 | `free()` を呼ぶまで永続 |
| **リスク** | スタックオーバーフロー | メモリリーク、ダングリングポインタ |

```
【メモリ空間の構造】
+------------------------------------+ (高位アドレス)
|  スタック領域 (Stack)              |
|  - ローカル変数・関数引数           |
|  - 自動で確保・解放される          |
|                 |                  |
|                 v (下に向かって成長) |
|                                    |
|                 ^ (上に向かって成長) |
|                 |                  |
|  ヒープ領域 (Heap)                 |
|  - malloc / calloc / realloc       |
|  - 手動で free 必須                |
+------------------------------------+
|  データ領域 / テキスト（コード）領域|
+------------------------------------+ (低位アドレス)
```

---

### ② 動的メモリ管理の4大関数 (`<stdlib.h>`)

動的メモリ確保・操作には `<stdlib.h>` に定義されている標準関数を使用します。

#### 1. `malloc` (Memory Allocation)
指定されたバイト数のメモリをヒープ領域から確保します。確保された領域の中身は**初期化されず不定値**（ゴミデータ）が入っています。

```c
// 100バイトのメモリを確保
char *ptr = (char *)malloc(100);
if (ptr == NULL) {
    // メモリ確保失敗時のエラーハンドリング
    return -1;
}
```

#### 2. `calloc` (Clear Allocation)
要素数と1要素あたりのサイズを指定して確保します。`malloc` と異なり、確保された領域は**すべて `0` でクリア初期化**されます。

```c
// int型10個分の領域を確保し、0で初期化
int *arr = (int *)calloc(10, sizeof(int));
if (arr == NULL) {
    return -1;
}
```

#### 3. `realloc` (Re-Allocation)
すでに確保されたヒープ領域のサイズを変更（拡大・縮小）します。
元の場所の直後を拡張できない場合、別の広いアドレスへデータを全コピーした上で自動的に旧領域を解放し、新しいポインタを返します。

```c
// 既存の領域を2倍のサイズ（20個分）に拡張
int *new_arr = (int *)realloc(arr, sizeof(int) * 20);
if (new_arr == NULL) {
    // 失敗しても元の arr は解放されていないため手動で free(arr) が必要
    free(arr);
    return -1;
}
arr = new_arr;
```

#### 4. `free` (Deallocation)
`malloc` / `calloc` / `realloc` で確保したヒープ領域をOSへ返却・解放します。

```c
free(ptr);
ptr = NULL; // 安全のため解放後は必ず NULL を代入する習慣をつける
```

### ③ 動的配列の容量倍増（Amortized O(1)）アルゴリズム

固定長の配列では、ファイル数や要素数が事前予測できない場合に要素あふれを起こします。
これを解決するのが**動的配列（Dynamic Array）**です。

```
[初期状態: capacity = 4, count = 4]
+----+----+----+----+
| F1 | F2 | F3 | F4 |   (満杯！)
+----+----+----+----+

[要素追加時: realloc で capacity を 2倍 (8) に拡張]
+----+----+----+----+----+----+----+----+
| F1 | F2 | F3 | F4 | F5 |    |    |    |
+----+----+----+----+----+----+----+----+
                     ^
               count = 5, capacity = 8
```

1要素追加ごとに `realloc` で +1 サイズ拡大すると、データの全コピーが毎回発生して計算量が $O(N^2)$ に悪化します。
しかし**容量を2倍ずつ拡張**することで、コピーコストが均等化され、1要素あたりの追加コストはならし計算量（Amortized Time Complexity）で **$O(1)$** となり、非常に効率的になります。

## 2. 現場で飛び交う業界用語辞典

- **メモリリーク (Memory Leak)**:
  `malloc` 等で確保したヒープ領域を `free` せずに放置し、アクセス不能なままメモリ消費が増え続ける現象。サーバーや常駐プログラムでは最終的にメモリ枯渇でクラッシュを引き起こす。
- **ダングリングポインタ (Dangling Pointer / ぶら下がりポインタ)**:
  `free()` で解放済みのメモリ領域を指し続けたままのポインタ。解放後に誤ってアクセスすると、未定義動作（データの破損やセグメンテーション違反）の原因となる。
- **二重解放 (Double Free)**:
  同じメモリ領域に対して2回 `free()` を呼び出すバグ。ヒープの管理情報が破壊され、セキュリティ脆弱性（任意コード実行など）の原因となる。
- **AddressSanitizer (ASan)**:
  コンパイル時に `-fsanitize=address` オプションを付与することで、実行時にメモリリークや境界外アクセス、Double Free 等を即座に検知・レポートしてくれる開発用ツール。

## 3. ボス戦ミッション（実装仕様）

本フロアでは、`gear/include/file_list.h` にて宣言されているファイルリスト構造体 `FileList` の動的メモリ管理ロジックを `file_list.c` に実装する。

### 構造体定義 (`gear/include/file_list.h`)

```c
typedef struct {
    char *filename;     // 動的確保したファイル名文字列へのポインタ
    char extension[32]; // 固定長拡張子バッファ (例: "c", "txt")
    size_t size_bytes;  // ファイルサイズ
} FileItem;

typedef struct {
    FileItem *items;    // FileItem の動的配列ポインタ
    size_t count;       // 現在格納されている要素数
    size_t capacity;    // 現在確保されている最大容量
} FileList;
```

---

### 実装すべき3つの関数仕様

#### 1. `int init_file_list(FileList *list, size_t initial_capacity)`
- **説明**: `FileList` 構造体を初期化し、指定された初期容量 `initial_capacity` 分の `FileItem` 配列をヒープ領域に確保する。
- **引数**:
  - `list`: 初期化対象の `FileList` ポインタ
  - `initial_capacity`: 初期確保容量
- **戻り値**: 成功時は `0`、引数不正（`list == NULL` や `initial_capacity == 0`）または `malloc` 失敗時は `-1`。
- **処理詳細**:
  - `list->items` を `malloc(sizeof(FileItem) * initial_capacity)` で確保。
  - `list->count = 0`
  - `list->capacity = initial_capacity`

#### 2. `int add_file_item(FileList *list, const char *filename, const char *ext, size_t size_bytes)`
- **説明**: リストに新しいファイル情報を1件追加する。容量不足時は容量を2倍に拡張する。
- **引数**:
  - `list`: 対象の `FileList` ポインタ
  - `filename`: ファイル名文字列
  - `ext`: 拡張子文字列
  - `size_bytes`: バイトサイズ
- **戻り値**: 成功時は `0`、引数不正（`list == NULL`, `list->items == NULL`, `filename == NULL`, `ext == NULL`）またはメモリ確保失敗時は `-1`。
- **処理詳細**:
  - `list->count == list->capacity` の場合、`realloc` を使って容量を `list->capacity * 2` に拡張。
  - `filename` 用のメモリを `malloc(strlen(filename) + 1)` で動的確保し、文字列をコピー。
  - `ext` を `extension[32]` バッファへ安全にコピー（末尾ヌル文字 `\0` を保証）。
  - `size_bytes` を設定し、`list->count++` を行う。

#### 3. `void free_file_list(FileList *list)`
- **説明**: `FileList` が保持しているすべてのヒープメモリを安全に解放し、初期状態にリセットする。
- **引数**:
  - `list`: 対象の `FileList` ポインタ
- **処理詳細**:
  - `list` が `NULL` の場合は即座にリターン。
  - 各要素 (`0` から `count - 1`) の `items[i].filename` をすべて `free` する。
  - `list->items` 自体を `free` する。
  - `list->items = NULL`, `list->count = 0`, `list->capacity = 0` へリセット。
