## 1. この階層で学ぶC言語の核心

### ① `#include` と `main` 関数（すべての始まり）
C言語のプログラムは、必ず `main` という名前の関数から実行が開始されます。画面に文字を表示するための標準道具箱 `<stdio.h>`（Standard Input/Output Header）を冒頭で読み込みます。

```c
#include <stdio.h>

int main(void) {
    printf("Link Start!\n");
    return 0; // OSに「正常終了（エラーなし）」を伝える数値
}
```

### ② データ型とフォーマット指定子（型にはめる美学）
C言語では、扱うデータの種類（型）を明確に宣言しなければなりません。また、`printf` で変数を表示する際は「どんな形式で埋め込むか」を指定する**フォーマット指定子**を使います。

| データ型 | 意味 | `printf` 指定子 | 応用テクニック（桁揃え・小数制御） |
| :--- | :--- | :--- | :--- |
| `const char *` | 文字列 | `%s` | `"%s"` で文字列をそのまま埋め込む |
| `int` | 整数 | `%d` | `"%04d"` と書くと `4` 桁のゼロ埋め（例: `0001`）になる |
| `double` | 倍精度実数（小数） | `%f` | `"%.1f"` と書くと小数点以下 `1` 桁まで表示（例: `42.5`） |

> 💡 **注意**: `printf` の中で `%` という記号そのものを画面に表示したい場合は、`%%` と2つ続けて記述します（例: `"%.1f%%\n"` ➔ `42.5%`）。

---

## 2. 現場で飛び交う業界用語辞典

- **CLI（Command Line Interface / 黒い画面）**:
  文字（コマンド）だけでコンピュータに命令を下す画面のこと。GUI（マウス操作）よりも圧倒的に高速で、自動化が容易なためプロの現場では必須となる。
- **コンパイル（Compile）とバイナリ（Binary）**:
  人間が書いたC言語のソースコード（`.c`）は、そのままではCPUには理解できない。コンパイラ（`gcc` や `clang`）を使って、CPUが直接実行できる「0と1の機械語ファイル（バイナリ）」に翻訳する作業をコンパイルと呼ぶ。
- **標準出力（stdout）と終了ステータス（Exit Status）**:
  プログラムが画面に出す通常の文字出力を `stdout` と呼ぶ。そして `main` 関数の最後にある `return 0;` は、プログラム終了時にOSへ返す「終了コード（0＝成功、0以外＝異常終了）」である。

#include <stdio.h>
#include <string.h>

int main(int argc, char *argv[]) {
    /* 1. 引数が存在しない場合 */
    if (argc < 2) {
        printf("[ERROR] NO COMMAND SPECIFIED\n");
        return 1;
    }

    /* 2. -h オプション */
    if (strcmp(argv[1], "-h") == 0) {
        printf("USAGE: gear <stat|memo|clean> [options]\n");
        return 0;
    }

    /* 3. -v オプション */
    if (strcmp(argv[1], "-v") == 0) {
        printf("GEAR VERSION 1.0.0-aincrad\n");
        return 0;
    }

    /* 4. memo コマンド */
    if (strcmp(argv[1], "memo") == 0) {
        if (argc < 3) {
            printf("[ERROR] EMPTY MEMO\n");
            return 1;
        }

        printf("MEMO: ");
        for (int i = 2; i < argc; i++) {
            printf("%s", argv[i]);
            if (i < argc - 1) {
                printf(" ");
            }
        }
        printf("\n");
        return 0;
    }

    /* 5. 未知のコマンド */
    printf("[ERROR] UNKNOWN COMMAND: %s\n", argv[1]);
    return 1;
}

## 1. この階層で学ぶC言語の核心

### ① コマンドライン引数（`int argc, char *argv[]`）
C言語の `main` 関数は、起動時にコマンドラインから渡された引数を受け取ることができます。

```c
int main(int argc, char *argv[]) {
    // argc : 引数の個数 (Argument Count)
    // argv : 引数文字列の配列 (Argument Vector)
}
```

- **`argc` (Argument Count)**: プログラム名自体を含む引数の総数（整数値）です。
  - 例: `./floor_runner -h` と実行した場合、`argc` は `2` になります。
- **`argv` (Argument Vector)**: 各引数文字列へのポインタ配列です。
  - `argv[0]` : 実行されたプログラムのパス（例: `"./floor_runner"`）
  - `argv[1]` : 第1引数（例: `"-h"`）
  - `argv[2]` : 第2引数（例: `"memo"`）

> ⚠️ **重要**: `argv[argc]` は常に `NULL` です。存在しない `argv[1]` にアクセスしようとするとセグメンテーション違反（クラッシュ）の原因になります。必ず事前に `argc` の値をチェックしてください。

---

### ② 文字列の等価比較（`strcmp` 関数と `<string.h>`）
C言語では、`argv[1] == "-h"` のように `==` 演算子で文字列の内容同士を直接比較することはできません（アドレスの比較になってしまいます）。
文字列の内容が一致しているかを調べるには、`<string.h>` ヘッダをインクルードし、`strcmp` 関数（String Compare）を使用します。

```c
#include <string.h>

if (strcmp(argv[1], "-h") == 0) {
    // argv[1] と "-h" が完全に一致する場合（返り値が 0）
}
```

| 比較結果 | `strcmp(s1, s2)` の返り値 | 意味 |
| :--- | :--- | :--- |
| `s1` と `s2` が完全一致 | `0` | 両方の文字列が等しい |
| `s1` が `s2` より辞書順で前 | 負の値（`< 0`） | `s1` の方が小さい |
| `s1` が `s2` より辞書順で後 | 正の値（`> 0`） | `s1` の方が大きい |

---

### ③ 条件分岐（`if-else`）と 早期リターン（Early Return）
プログラムのガード節として「異常な入力や特定の操作」を関数の冒頭で検知し、すぐに処理を終了して抜け出す手法を**早期リターン（Early Return）**と呼びます。

```c
// 1. 引数が存在しない場合のガード（早期リターン）
if (argc < 2) {
    printf("[ERROR] NO COMMAND SPECIFIED\n");
    return 1; // エラー終了
}

// 2. 引数に応じた分岐処理
if (strcmp(argv[1], "-h") == 0) {
    printf("USAGE: ...\n");
    return 0; // 成功終了
}
```

ネスト（深くなる条件分岐）を避け、コードの可読性と保守性を劇的に向上させるプロの必須テクニックです。

---

### ④ 反復処理（`for` ループ）による可変長引数の連結
可変個の引数を順番に処理したい場合は `for` ループを使用します。

```c
for (int i = 2; i < argc; i++) {
    printf("%s", argv[i]);
    if (i < argc - 1) {
        printf(" "); // 最後の要素以外はスペースを入れる
    }
}
printf("\n");
```

- **パース（引数解析 / Argument Parsing）**:
  ユーザーがコマンドラインに入力した生の文字列群（`argv`）を解析し、プログラムが理解できる命令やオプション構造体に変換する処理のこと。

#include <string.h>
#include "safe_str.h"

int safe_str_copy(char *dest, size_t dest_size, const char *src) {
    if (!dest || !src || dest_size == 0) {
        return -1;
    }

    size_t src_len = strlen(src);
    if (src_len < dest_size) {
        memcpy(dest, src, src_len + 1);
        return 0;
    } else {
        memcpy(dest, src, dest_size - 1);
        dest[dest_size - 1] = '\0';
        return 1;
    }
}

int safe_path_join(char *dest, size_t dest_size, const char *dir, const char *file) {
    if (!dest || !dir || !file || dest_size == 0) {
        return -1;
    }

    size_t dir_len = strlen(dir);
    size_t file_len = strlen(file);
    int has_slash = (dir_len > 0 && dir[dir_len - 1] == '/');

    size_t needed = dir_len + (has_slash ? 0 : 1) + file_len + 1;
    if (needed > dest_size) {
        return -1;
    }

    memcpy(dest, dir, dir_len);
    size_t pos = dir_len;
    if (!has_slash) {
        dest[pos++] = '/';
    }
    memcpy(dest + pos, file, file_len);
    pos += file_len;
    dest[pos] = '\0';

    return 0;
}

## 1. この階層で学ぶC言語の核心

### ① 文字配列 `char buf[N]` と 終端文字 `\0`
C言語における文字列は、`char` 型の要素がメモリ上に連続して並んだ配列です。
文字列の終わりを識別するために、必ず末尾に `\0` (ASCIIコード `0`) を配置しなければなりません。

```text
[ 'S' ][ 'A' ][ 'O' ][ '\0' ][ ? ][ ? ]
  0      1      2      3      4    5   (インデックス)
```

例えば `"SAO"` という3文字の文字列を格納するには、終端文字 `\0` の分の1バイトを含めて、最低でも **4バイト** の配列サイズが必要となります。

```c
char buf[4] = "SAO"; // OK: 'S', 'A', 'O', '\0' が格納される
char bad[3] = "SAO"; // 危険: '\0' が入らず、文字列として破壊される！
```

---

### ② バッファオーバーフロー（BOF）の脅威
確保したメモリ領域（バッファ）を超えてデータを書き込んでしまう現象を **バッファオーバーフロー** と呼びます。
古くから存在する危険な関数 `strcpy` や `strcat` は、コピー先のバッファサイズを検証しないため、容易にバッファオーバーフローを引き起こします。

```c
char dest[5];
strcpy(dest, "EVERYDAY HERO"); // 超危険！ destの範囲を超えてメモリを破壊する
```

バッファオーバーフローが発生すると、プログラムのクラッシュ（Segmentation Fault）を引き起こすだけでなく、悪意ある第三者によってメモリ構造が書き換えられ、任意のコードを実行される脆弱性につながります。

---

### ③ オフバイワンエラー（Off-by-One Error）
プログラマを悩ませる典型的なバグが、境界値を「1」だけ見誤る **オフバイワンエラー** です。

```c
char buf[10];
// 10文字コピーしてしまい、'\0' を書くスペースがなくなる例
for (int i = 0; i <= 10; i++) { // ループ回数が11回になってしまっている
    buf[i] = src[i];
}
```

特に「バッファサイズ `dest_size` に対して最大何文字コピーできるか？」を考える際、終端文字 `\0` のための1バイトを忘れると、容易にオフバイワンエラーが発生します。
最大コピー可能文字数は常に **`dest_size - 1` 文字** です。

---

### ④ 入力のサニタイズと防御的プログラミング
外部からの入力や関数の引数は、常に危険を孕んでいます。
関数を設計する際は、以下のチェック（サニタイズ）を徹底する **防御的プログラミング** が不可欠です。

1. **NULLポインタチェック**: `dest` や `src` が `NULL` でないか？
2. **バッファサイズチェック**: `dest_size` が `0` でないか？
3. **境界値の厳守**: コピー処理後、どのような場合でも必ず末尾に `\0` を付与する。

## 2. 現場で飛び交う業界用語辞典

- **バッファオーバーフロー (Buffer Overflow / BOF)**:
  準備したメモリ領域（バッファ）を超えてデータが書き込まれ、隣接するメモリ領域が破損するセキュリティ脆弱性。
- **オフバイワンエラー (Off-by-One Error)**:
  ループの反復回数や配列のインデックス計算で「1」だけズレてしまう計算ミス。配列の領域外アクセスを引き起こす主原因。
- **AddressSanitizer (ASan)**:
  コンパイラ（GCC/Clang）の強力なメモリ検証ツール。`-fsanitize=address` オプションをつけてビルドすることで、境界外アクセスやメモリリークをリアルタイムに検知・報告してくれる。
- **防御的プログラミング (Defensive Programming)**:
  「引数にNULLが渡されるかもしれない」「バッファサイズが足りないかもしれない」といった不測の事態や誤用をあらかじめ想定し、安全装置（ガード条件）を組み込む設計手法。

### 関数の詳細仕様

#### 1. `int safe_str_copy(char *dest, size_t dest_size, const char *src)`
文字列 `src` をバッファ `dest` へ安全にコピーします。

- **引数エラーチェック**:
  - `dest == NULL` または `src == NULL` または `dest_size == 0` の場合、直ちに `-1` を返します。
- **コピー動作**:
  - `src` から最大 `dest_size - 1` 文字を `dest` にコピーします。
  - **どのような場合でも、必ず `dest` の末尾（`dest[dest_size - 1]` または実際の文字数の直後）に `\0` を付与します。**
- **戻り値**:
  - 切り詰めが発生せずに完全にコピーできた場合: `0`
  - バッファサイズ不足により切り詰め（Truncation）が発生した場合: `1`
  - 引数エラー等の不整合が発生した場合: `-1`

---

#### 2. `int safe_path_join(char *dest, size_t dest_size, const char *dir, const char *file)`
ディレクトリパス `dir` とファイル名 `file` を、間に `/` を挟んで結合し `dest` に格納します。

- **引数エラーチェック**:
  - `dest == NULL` または `dir == NULL` または `file == NULL` または `dest_size == 0` の場合、直ちに `-1` を返します。
- **パス結合動作**:
  - `dir` の末尾にすでに `/` が存在する場合は `/` を重複させず、そのまま `file` を結合します（例: `"/usr/local/"` + `"bin"` ➔ `"/usr/local/bin"`）。
  - `dir` の末尾に `/` が存在しない場合は `/` を1つ挟んで結合します（例: `"/usr/local"` + `"bin"` ➔ `"/usr/local/bin"`）。
- **バッファオーバーフロー防御**:
  - 結合後の完全なパス（終端文字 `\0` を含む）が `dest_size` に収まらない場合は、`dest` を変更せず（またはコピーを中断し）直ちに `-1` を返します。
  - 成功した場合は必ず末尾に `\0` を付与し、`0` を返します。

## 1. この階層で学ぶC言語の核心

これまでの階層では、単一の `.c` ファイル内にすべての処理（`main` 関数など）を記述してきました。
しかし、プログラムの規模が大きくなると、コードの視認性が著しく低下し、複数人での開発や共通処理の再利用が困難になります。

### ① 関数分割とプロトタイプ宣言

処理のかたまりを独立した「関数」として切り出すことを**関数分割**と呼びます。
C言語では、コンパイラはコードを**上から下へ**順に読み進めます。そのため、ある関数 `A` の中で別の関数 `B` を呼び出す場合、原則として `B` の定義または宣言が `A` より前に存在しなければなりません。

```c
#include <stdio.h>

// プロトタイプ宣言（関数の「看板」を前に立てておく）
int calc_sum(int a, int b);

int main(void) {
    int total = calc_sum(10, 20); // コンパイラは関数の型と引数を知っているためOK
    printf("Total: %d\n", total);
    return 0;
}

// 関数の実体（本体）の定義
int calc_sum(int a, int b) {
    return a + b;
}
```

#### プロトタイプ宣言とは？
関数の名前、戻り値の型、引数の型・個数だけをコンパイラに事前に知らせる宣言です。
プロトタイプ宣言があることで、関数の実体がコードの下部や**別のファイル**にあっても、コンパイラは型チェックを正しく行うことができます。

---

### ② ヘッダファイル（`.h`）と `#include`

別の `.c` ファイルで定義された関数を呼び出したい場合、呼び出し側でその関数のプロトタイプ宣言が必要になります。
しかし、利用する側のファイルごとに毎回手動でプロトタイプ宣言を書くのは非効率的でミスのもとです。

そこで用いられるのが**ヘッダファイル（`.h`）**です。

- **`calc.h`** : プロトタイプ宣言や定数定義、構造体宣言を記述する。
- **`calc.c`** : `calc.h` で宣言された関数の「実際の処理（定義）」を記述する。
- **`main.c`** : `#include "calc.h"` を書き、宣言された関数を利用する。

#### `#include <...>` と `#include "..."` の違い
| 形式 | 検索対象ディレクトリ | 主な用途 |
| :--- | :--- | :--- |
| `#include <stdio.h>` | システムの標準ライブラリディレクトリ | `stdio.h`, `stdlib.h`, `string.h` 等 |
| `#include "calc.h"` | カレントディレクトリ（自作ファイルの場所） | 開発者が自作したヘッダファイル |

---

### ③ インクルードガード（`#ifndef`）の絶対的役割

複数のファイルから同じヘッダファイルが間接的にインクルードされると、同一のプロトタイプ宣言や型定義が多重に読み込まれ、**多重定義エラー（Redefinition error）**が発生します。

これを防止するための必須構造が**インクルードガード**です。

```c
#ifndef CALC_H
#define CALC_H

// ここにプロトタイプ宣言などを記述する
int calc_storage_percent(long used, long total);
int calc_player_rank(int score);

#endif /* CALC_H */
```

#### 動作の仕組み
1. 初めて `calc.h` が読み込まれたとき、マクロ `CALC_H` は未定義です（`#ifndef CALC_H` が真）。
2. 直後の `#define CALC_H` により `CALC_H` が定義され、中身が処理されます。
3. 同じビルド単位で2回目以降に `calc.h` が読み込まれると、`CALC_H` は既に定義されているため、`#ifndef CALC_H` から `#endif` までの内容がすべてスキップされます。

---

### ④ 分割コンパイルの仕組み

C言語では、複数の `.c` ファイルを個別にコンパイルしてオブジェクトファイル（`.o`）を作成し、最後にそれらを結合して1つの実行ファイル（バイナリ）を生成します。

```bash
# 1. 各ソースファイルを個別コンパイル（-c オプションでオブジェクトファイル生成）
gcc -std=c11 -Wall -Wextra -Werror -c main.c -o main.o
gcc -std=c11 -Wall -Wextra -Werror -c calc.c -o calc.o

# 2. オブジェクトファイルをリンクして実行ファイルを生成
gcc main.o calc.o -o floor_runner
```

### ⑤ `Makefile` の書き方とビルド自動化

ソースファイルの数が増えると、手動で `gcc` コマンドを何度も打つのは困難になります。
ビルド手順を自動化するツールが `make` であり、その設定ファイルが `Makefile` です。

#### 構文規則
```makefile
ターゲット: 依存ファイル1 依存ファイル2
	実行するコマンド（※行頭は必ず「TAB文字」でインデントする）
```

#### 代表的な `Makefile` 例
```makefile
CC = gcc
CFLAGS = -std=c11 -Wall -Wextra -Werror

# デフォルトターゲット
all: floor_runner

# 最終バイナリの生成（リンカ）
floor_runner: main.o calc.o
	$(CC) $(CFLAGS) -o floor_runner main.o calc.o

# 各オブジェクトファイルの生成（コンパイル）
main.o: main.c calc.h
	$(CC) $(CFLAGS) -c main.c -o main.o

calc.o: calc.c calc.h
	$(CC) $(CFLAGS) -c calc.c -o calc.o

# クリーンアップルール
clean:
	rm -f *.o floor_runner
```

## 2. 現場で飛び交う業界用語辞典

- **リファクタリング（Refactoring）**:
  プログラムの外部から見た挙動（出力結果）を変えることなく、内部のコード構造を整理・改善する作業のこと。関数の分割や重複コードの除去が含まれる。
- **モジュール化（Modularization）**:
  大規模なシステムを機能ごとに独立した部品（モジュール）に切り分けること。保守性、再利用性、テスト容易性が飛躍的に向上する。
- **リンカ（Linker）**:
  コンパイルによって生成された複数のオブジェクトファイル（`.o`）やライブラリを結合し、1つの実行可能ファイル（バイナリ）を作成するプログラムのこと。関数の呼び出し元と呼び出し先のนี่アドレスを結びつける（リンクする）。

## 1. この階層で学ぶC言語の核心

### ① メモリ空間とアドレス演算子 `&`・間接参照演算子 `*`
コンピュータのメモリ（RAM）は、1バイトごとに固有の「番地（アドレス）」が割り当てられた巨大なロッカーのようなものです。

```text
+-------------------+-------------------+-------------------+
| メモリ番地        | 変数名            | 値                |
+-------------------+-------------------+-------------------+
| 0x7ffd5f81a02c    | level             | 10                |
| 0x7ffd5f81a030    | ptr               | 0x7ffd5f81a02c    |
+-------------------+-------------------+-------------------+
```

- **アドレス演算子 `&`**: 変数が配置されているメモリの番地を取得します。
  `&level` は 「`level` 変数が置かれているメモリ番地」を表します。
- **ポインタ変数**: メモリ番地（アドレス）を記憶するための専用変数です。
  `int *ptr = &level;` は 「`int` 型の番地を格納する変数 `ptr` に `level` の番地を代入する」という意味になります。
- **間接参照演算子（デファレンス） `*`**: ポインタが指し示している番地の「中身」を読み書きします。
  `*ptr = 20;` と書くと、`ptr` が指す番地（`level` の領域）の値が `20` に書き換わります。

```c
int level = 10;
int *ptr = &level; // ptr に level のアドレスを格納

printf("levelの値: %d\n", level);     // 10
printf("levelの番地: %p\n", (void*)&level); // 0x7ffd5f81a02c
printf("ptrの保持する値: %p\n", (void*)ptr); // 0x7ffd5f81a02c
printf("*ptrの指す値: %d\n", *ptr);   // 10

*ptr = 20; // ptrを経由してlevelを直接書き換える！
printf("変更後のlevel: %d\n", level); // 20
```

---

### ② 値渡し（Pass by Value）vs ポインタ渡し（Pass by Pointer）
C言語の関数引数は、デフォルトではすべて**値渡し（コピー）**です。

#### 【危険】値渡しの罠
```c
void level_up_bad(int level) {
    level++; // 引数としてコピーされたローカル変数 level を増やしているだけ！
}

int main(void) {
    int my_level = 10;
    level_up_bad(my_level);
    // my_level は 10 のまま！呼び出し元の値は変化しない！
    return 0;
}
```

```text
[main のスタック領域]          [level_up_bad のスタック領域]
+--------------------+        +--------------------+
| my_level: 10       | --コピー->| level: 10         |
+--------------------+        +--------------------+
  (変化なし!)                    (11 に増やすが関数終了で消滅)
```

#### 【解決】ポインタ渡し
呼び出し元の変数の「番地」を関数に渡すことで、関数の中から呼び出し元の実体を直接書き換えることができます。

```c
void level_up_good(int *level_ptr) {
    if (level_ptr != NULL) {
        (*level_ptr)++; // 指し示している先の実体を直接インクリメント
    }
}

int main(void) {
    int my_level = 10;
    level_up_good(&my_level); // アドレスを渡す
    // my_level は 11 に更新される！
    return 0;
}
```

```text
[main のスタック領域]          [level_up_good のスタック領域]
+--------------------+        +--------------------+
| my_level: 10 <=====|========| level_ptr: 0x...02c| (my_levelの番地を保持)
+--------------------+        +--------------------+
  (*level_ptr)++ により 11 に直接書き換わる！
```

---

### ③ NULLポインタとセグメンテーション違反（SIGSEGV）
ポインタがどこも指していない状態を表す特別な値が `NULL`（通常はアドレス `0`）です。

存在しない無効なアドレス（`NULL` や解放済み領域、許可されていない領域）にアクセス（間接参照 `*`）しようとすると、OSのメモリ保護機能によりプログラムは即座に強制終了します。これが**セグメンテーション違反（Segmentation Fault / SIGSEGV）**です。

```c
int *ptr = NULL;
*ptr = 100; // 💥 CRASH! セグメンテーション違反が発生！
```

#### 防御的プログラミング：NULLチェックの徹底
ポインタを引数として受ける関数では、間接参照する前に必ず `NULL` チェックを行うのが鉄則です。

```c
int safe_read_hp(const int *hp_ptr) {
    // ポインタが NULL でないか必ず確認する
    if (hp_ptr == NULL) {
        return -1; // エラー状態を示す値を返す
    }
    return *hp_ptr;
}
```

---

### ④ メモリ境界外アクセス（Off-by-One error / バッファオーバーフロー）
配列の要素数が `N` の場合、有効なインデックスは `0` から `N - 1` までです。
ループ条件を `i <= N` と誤ってしまうと、配列の外側のメモリ（`N` 番目の領域）にアクセスしてしまいます。

```text
配列 arr[5] のメモリ配置 (size = 5)
+----------+----------+----------+----------+----------+------------------+
| arr[0]   | arr[1]   | arr[2]   | arr[3]   | arr[4]   | 🚨 arr[5] (侵犯!) |
+----------+----------+----------+----------+----------+------------------+
  有効インデックス: 0, 1, 2, 3, 4                         境界外アクセス！
```

---

### ⑤ AddressSanitizer（ASan）によるデバッグとログの読み方
コンパイル時に `-fsanitize=address -g` フラグを付与すると、LLVM/GCC の AddressSanitizer (ASan) が有効化され、メモリ違反が発生した瞬間に詳細なエラーログを出力してくれます。

#### ASan ログの解読ガイド

```text
=================================================================
==12345==ERROR: AddressSanitizer: global-buffer-overflow on address 0x...
READ of size 4 at 0x... thread T0
    #0 0x... in init_array /path/to/main.c:25
    #1 0x... in main /path/to/main.c:45

0x... is located 0 bytes to the right of global variable 'arr' defined in 'main.c:10'
SUMMARY: AddressSanitizer: global-buffer-overflow /path/to/main.c:25 in init_array
=================================================================
```

1. **エラー種別 (`ERROR: AddressSanitizer: ...`)**:
   - `global-buffer-overflow` / `stack-buffer-overflow`: 配列等の境界外アクセス。
   - `SEGV on unknown address`: NULLポインタや不正アドレス参照。
2. **発生箇所 (`#0 0x... in function /path/to/file.c:line`)**:
   エラーが発生した関数名と行番号（上記なら `main.c` の 25 行目）。
3. **詳細説明 (`is located ... bytes to the right of...`)**:
   変数の境界から何バイトオーバーしたかを表示。

## 2. 現場で飛び交う業界用語辞典

- **ポインタ（Pointer）**:
  メモリ上のアドレス（番地）を保持する変数。C言語において最も強力であり、最もバグを生み出しやすい要素。
- **デファレンス（Dereference / 間接参照）**:
  ポインタ変数に `*` を付けて、そのポインタが指し示しているアドレスに格納されているデータにアクセスすること。
- **SIGSEGV（Segmentation Fault / セグフォ）**:
  アクセス権限のないメモリ領域を読み書きしようとした時に、OSから送られるシグナル（シグナル番号11）。
- **Off-by-One エラー**:
  ループの境界条件を「1」間違えることで発生するバグ（`<` を `<=` と書く、`0` 開始か `1` 開始かを勘違いするなど）。
- **AddressSanitizer（ASan）**:
  Googleが開発した高速メモリバグ検出ツール。コンパイルオプション `-fsanitize=address` を付けるだけで利用可能。

int parse_args(int argc, char *argv[], GearConfig *out_config) {
    if (out_config == NULL || argc < 2) {
        return -1;
    }

    memset(out_config, 0, sizeof(GearConfig));
    snprintf(out_config->target_path, sizeof(out_config->target_path), "%s", "./dungeon_box");

    const char *subcmd = argv[1];

    if (strcmp(subcmd, "-h") == 0 || strcmp(subcmd, "--help") == 0) {
        out_config->command = CMD_HELP;
        return 0;
    }

    if (strcmp(subcmd, "-v") == 0 || strcmp(subcmd, "--version") == 0) {
        out_config->command = CMD_VERSION;
        return 0;
    }

    if (strcmp(subcmd, "stat") == 0) {
        out_config->command = CMD_STAT;
        return 0;
    }

    if (strcmp(subcmd, "memo") == 0) {
        out_config->command = CMD_MEMO;
        if (argc < 3 || argv[2][0] == '\0') {
            return -1;
        }
        snprintf(out_config->memo_text, sizeof(out_config->memo_text), "%s", argv[2]);
        return 0;
    }

    if (strcmp(subcmd, "clean") == 0) {
        out_config->command = CMD_CLEAN;
        for (int i = 2; i < argc; i++) {
            if (strcmp(argv[i], "--dry-run") == 0) {
                out_config->dry_run = true;
            } else if (strcmp(argv[i], "--verbose") == 0 || strcmp(argv[i], "-v") == 0) {
                out_config->verbose = true;
            } else {
                snprintf(out_config->target_path, sizeof(out_config->target_path), "%s", argv[i]);
            }
        }
        return 0;
    }

    return -1;
}

> 構造体（`struct`）とは、プログラムにおける『魂の設計図』だ。
> 複数の属性を一つにまとめ、カプセル化し、整然としたモデルとして扱う技術を身につけよ。

## 1. この階層で学ぶC言語の核心

これまでの階層では `int` や `char[]` といった単一の型を扱ってきましたが、現実のアプリケーション開発では「プレイヤーの名前・LV・HP・MP」や「コマンドライン引数の解析結果（コマンド種別・ターゲットパス・フラグ群）」のように、複数の異なる型のデータを1つのまとまりとして管理する必要があります。

これを実現するのが **構造体（`struct`）** と **列挙型（`enum`）** です。

---

### ① 構造体（`struct`）とメンバーアクセス

構造体は、異なるデータ型の変数を1つのグループにまとめるカスタムデータ型を作成する仕組みです。

```c
/* 構造体の定義 */
struct Player {
    char name[32];
    int level;
    int hp;
    double exp;
};

/* 構造体変数の宣言と初期化 */
struct Player p1 = {"Kirito", 10, 250, 1250.5};

/* メンバーへのアクセス（ドット演算子 .） */
printf("Player: %s (LV: %d)\n", p1.name, p1.level);
```

#### メモリ配置と構造体の本質
構造体の各メンバーはメモリ上に連続して配置されます。これにより、複数の関連データを関数の引数として渡す際も、構造体1つ（またはそのポインタ）を渡すだけで済むようになります。

---

### ② 型にエイリアスをつける `typedef`

C言語では構造体を使う際、毎回 `struct Player` と書く必要がありますが、`typedef` を使うことで簡潔な型名を定義できます。

```c
/* typedef を用いた構造体定義 */
typedef struct {
    char name[32];
    int level;
    int hp;
} Player;

/* struct キーワードなしで型として利用可能 */
Player p1;
p1.level = 15;
```

---

### ③ 列挙型（`enum`）による状態の表現

プログラム内で「コマンドの種類」や「プレイヤーの状態」を表現する際、魔法の数字（マジックナンバー: `0`, `1`, `2` ...）を直接使うとコードの読解性が著しく低下します。
`enum` を使うことで、一連の定数に名前を与えることができます。

```c
typedef enum {
    CMD_NONE = 0,
    CMD_HELP,     /* 1 */
    CMD_VERSION,  /* 2 */
    CMD_STAT,     /* 3 */
    CMD_MEMO,     /* 4 */
    CMD_CLEAN     /* 5 */
} GearCommand;

GearCommand cmd = CMD_STAT;
if (cmd == CMD_STAT) {
    /* ステータス画面の処理 */
}
```

---

### ④ 構造体ポインタとアロー演算子（`->`）

構造体を関数に引数として渡す際、値渡し（コピー）を行うとメモリ転送のオーバーヘッドが発生し、関数内での変更が呼び出し元に反映されません。
そのため、実務では **構造体のポインタ（アドレス渡し）** を使用します。

構造体ポインタ経由でメンバーにアクセスする場合は、ドット演算子 `.` ではなく **アロー演算子 `->`** を使用します。

```c
void reset_player(Player *p) {
    if (p == NULL) return;

    /* (*p).hp = 100; と同等だが、アロー演算子を用いるのが標準的 */
    p->hp = 100;
    p->level = 1;
}
```

#### アロー演算子 `->` の構文対比

| アクセス方法 | 記述形式 | 意味 |
| :--- | :--- | :--- |
| 直接アクセス | `config.dry_run = true;` | 実体（変数）のメンバーを変更 |
| 間接アクセス（展開） | `(*out_config).dry_run = true;` | ポインタを間接参照してからメンバー変更 |
| **アロー演算子** | `out_config->dry_run = true;` | ポインタ経由で直感的にメンバー変更（標準） |

## 2. 現場で飛び交う業界用語辞典

- **データモデリング（Data Modeling）**:
  現実世界の課題やシステム仕様を分析し、最適なデータ構造（構造体やフィールド定義）に落とし込む設計手法のこと。適切なデータモデルを定義できれば、処理ロジック（コード）は自然とシンプルかつ堅牢になる。
- **Config構造体（Configuration Structure）**:
  アプリケーション起動時の設定値やコマンドライン引数の解析結果を1つにまとめた構造体。プログラム全体に設定情報を安全かつ分かりやすく伝搬するために用いられる。
- **ドライラン（Dry-run）**:
  ファイルの削除や変更などを伴う本番処理を実行する前に、実際の変更を行わずに「どのような操作が行われるか」を事前確認・シミュレーションする実行モードのこと（例: `--dry-run` オプション）。

### `parse_args` 関数詳細仕様

`parse_args(int argc, char *argv[], GearConfig *out_config)` 関数を `arg_parser.c` に実装せよ。

#### 1. 共通事前条件とデフォルト初期化
1. `out_config == NULL` または `argc < 2` の場合は、処理を行わず即座に `-1` を返せ。
2. `out_config` が指す構造体全体をゼロクリア（`memset(out_config, 0, sizeof(GearConfig))` や全メンバ初期化）せよ。
3. デフォルトの `target_path` として `"./dungeon_box"` を設定せよ（文字列コピーを行うこと）。

#### 2. サブコマンドの解析 (`argv[1]`)
`argv[1]` の文字列に応じて以下の挙動を行え：

- **`-h` または `--help` の場合**:
  - `out_config->command` に `CMD_HELP` を設定し、`0` を返せ。
- **`-v` または `--version` の場合**:
  - `out_config->command` に `CMD_VERSION` を設定し、`0` を返せ。
- **`stat` の場合**:
  - `out_config->command` に `CMD_STAT` を設定し、`0` を返せ。
- **`memo` の場合**:
  - `out_config->command` に `CMD_MEMO` を設定せよ。
  - 次の引数 `argv[2]` が存在し（`argc >= 3`）、かつ空文字列（`""`）でない場合、その内容を `out_config->memo_text` に格納（コピー）して `0` を返せ。
  - もし `argv[2]` が存在しない、または空文字列（`argv[2][0] == '\0'`）の場合は `-1` を返せ。
- **`clean` の場合**:
  - `out_config->command` に `CMD_CLEAN` を設定せよ。
  - 以降の引数 `argv[2]` から `argv[argc - 1]` を順次解析せよ（後述の `clean` オプション解析ルール参照）。解析完了後、`0` を返せ。
- **上記以外の未知のサブコマンドの場合**:
  - `-1` を返せ。

#### 3. `clean` コマンドのオプション解析ルール
`argv[1]` が `"clean"` の場合、`i = 2` から `argc - 1` までの各引数 `argv[i]` について以下のように処理せよ：

- **`"--dry-run"` の場合**: `out_config->dry_run = true;`
- **`"--verbose"` または `"-v"` の場合**: `out_config->verbose = true;`
- **それ以外の文字列（ハイフンで始まらないパス指定等）の場合**:
  - `out_config->target_path` をその文字列で上書き更新せよ。

#include <stdio.h>
#include <stdlib.h>
#include <string.h>

static int run_tests(void) {
    GearConfig config;
    int res;

    /* Pattern 1: Invalid Arguments (argc < 2 or NULL out_config) */
    char *argv1[] = {"gear"};
    res = parse_args(1, argv1, &config);
    if (res != -1) {
        printf("[FAIL] Pattern 1: Expected -1 for argc < 2, got %d\n", res);
        return 1;
    }
    res = parse_args(2, argv1, NULL);
    if (res != -1) {
        printf("[FAIL] Pattern 1: Expected -1 for NULL out_config, got %d\n", res);
        return 1;
    }

    /* Pattern 2: Help / Version (-h or --version) */
    char *argv2[] = {"gear", "-h"};
    res = parse_args(2, argv2, &config);
    if (res != 0 || config.command != CMD_HELP || strcmp(config.target_path, "./dungeon_box") != 0) {
        printf("[FAIL] Pattern 2: Failed to parse '-h'\n");
        return 1;
    }

    char *argv2_v[] = {"gear", "--version"};
    res = parse_args(2, argv2_v, &config);
    if (res != 0 || config.command != CMD_VERSION) {
        printf("[FAIL] Pattern 2: Failed to parse '--version'\n");
        return 1;
    }

    /* Pattern 3: Stat command ("stat") */
    char *argv3[] = {"gear", "stat"};
    res = parse_args(2, argv3, &config);
    if (res != 0 || config.command != CMD_STAT || strcmp(config.target_path, "./dungeon_box") != 0 ||
        config.dry_run != false || config.verbose != false) {
        printf("[FAIL] Pattern 3: Failed to parse 'stat'\n");
        return 1;
    }

    /* Pattern 4: Memo command ("memo <text>") and error case */
    char *argv4_err[] = {"gear", "memo"};
    res = parse_args(2, argv4_err, &config);
    if (res != -1) {
        printf("[FAIL] Pattern 4: Expected -1 for memo without text, got %d\n", res);
        return 1;
    }

    char *argv4[] = {"gear", "memo", "System Alert: Boss Spawned"};
    res = parse_args(3, argv4, &config);
    if (res != 0 || config.command != CMD_MEMO || strcmp(config.memo_text, "System Alert: Boss Spawned") != 0) {
        printf("[FAIL] Pattern 4: Failed to parse 'memo'\n");
        return 1;
    }

    /* Pattern 5: Clean command with options ("clean --dry-run -v /custom/dir") */
    char *argv5[] = {"gear", "clean", "--dry-run", "-v", "/custom/dir"};
    res = parse_args(5, argv5, &config);
    if (res != 0 || config.command != CMD_CLEAN || strcmp(config.target_path, "/custom/dir") != 0 ||
        config.dry_run != true || config.verbose != true) {
        printf("[FAIL] Pattern 5: Failed to parse 'clean' with options\n");
        return 1;
    }

    /* Pattern 6: Invalid / Unknown Subcommand */
    char *argv6[] = {"gear", "unknown_cmd"};
    res = parse_args(2, argv6, &config);
    if (res != -1) {
        printf("[FAIL] Pattern 6: Expected -1 for unknown subcommand, got %d\n", res);
        return 1;
    }

    printf("ALL_PATTERNS_PASSED\n");
    return 0;
}

int main(void) {
    return run_tests();
}

#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include "file_list.h"

int init_file_list(FileList *list, size_t initial_capacity) {
    if (list == NULL || initial_capacity == 0) {
        return -1;
    }

    list->items = (FileItem *)malloc(sizeof(FileItem) * initial_capacity);
    if (list->items == NULL) {
        return -1;
    }

    list->count = 0;
    list->capacity = initial_capacity;
    return 0;
}

int add_file_item(FileList *list, const char *filename, const char *ext, size_t size_bytes) {
    if (list == NULL || list->items == NULL || filename == NULL || ext == NULL) {
        return -1;
    }

    if (list->count >= list->capacity) {
        size_t new_capacity = list->capacity * 2;
        FileItem *new_items = (FileItem *)realloc(list->items, sizeof(FileItem) * new_capacity);
        if (new_items == NULL) {
            return -1;
        }
        list->items = new_items;
        list->capacity = new_capacity;
    }

    FileItem *item = &list->items[list->count];

    item->filename = (char *)malloc(strlen(filename) + 1);
    if (item->filename == NULL) {
        return -1;
    }
    strcpy(item->filename, filename);

    strncpy(item->extension, ext, sizeof(item->extension) - 1);
    item->extension[sizeof(item->extension) - 1] = '\0';

    item->size_bytes = size_bytes;

    list->count++;
    return 0;
}

void free_file_list(FileList *list) {
    if (list == NULL) {
        return;
    }

    if (list->items != NULL) {
        for (size_t i = 0; i < list->count; i++) {
            if (list->items[i].filename != NULL) {
                free(list->items[i].filename);
                list->items[i].filename = NULL;
            }
        }
        free(list->items);
        list->items = NULL;
    }

    list->count = 0;
    list->capacity = 0;
}

# 【第7層：記憶の断頭台】〜ヒープの支配者〜

> **茅場晶彦からのシステム通達**:
> 「プレイヤー諸君、アインクラッド第7層『記憶の断頭台』へようこそ。

> 自由な領域――『ヒープ（Heap）』を解禁せよ。
> ただし忘れるな。ヒープ領域のメモリ確保と解放はすべて君自身の責任だ。
> 1バイトでも解放を怠ればメモリは腐敗し、存在しない領域を参照すればプログラムは断頭台の露と消える。
> メモリの生殺与奪権を握る『ヒープの支配者』となってみせよ」

---

## 1. この階層で学ぶC言語の核心

### ① スタック領域（Stack）とヒープ領域（Heap）の決定的な違い

C言語が扱うメモリ空間は、主に**スタック領域**と**ヒープ領域**の2つに大別されます。

| 比較項目 | スタック領域 (Stack) | ヒープ領域 (Heap) |
| :--- | :--- | :--- |
| **管理主体** | コンパイラ / OS（自動管理） | プログラマ（手動管理） |
| **サイズ決め** | コンパイル時にサイズが決定 | プログラム実行時に動的に決定 |
| **メモリサイズ** | 小さい（数MB程度、上限あり） | 巨大（利用可能RAMの全域） |
| **ライフサイクル** | スコープ（関数）を抜けると自動消滅 | `free()` を呼ぶまで永続 |
| **リスク** | スタックオーバーフロー | メモリリーク、ダングリングポインタ |

```
【メモリ空間の構造】
+------------------------------------+ (高位アドレス)
|  スタック領域 (Stack)              |
|  - ローカル変数・関数引数           |
|  - 自動で確保・解放される          |
|                 |                  |
|                 v (下に向かって成長) |
|                                    |
|                 ^ (上に向かって成長) |
|                 |                  |
|  ヒープ領域 (Heap)                 |
|  - malloc / calloc / realloc       |
|  - 手動で free 必須                |
+------------------------------------+
|  データ領域 / テキスト（コード）領域|
+------------------------------------+ (低位アドレス)
```

---

### ② 動的メモリ管理の4大関数 (`<stdlib.h>`)

動的メモリ確保・操作には `<stdlib.h>` に定義されている標準関数を使用します。

#### 1. `malloc` (Memory Allocation)
指定されたバイト数のメモリをヒープ領域から確保します。確保された領域の中身は**初期化されず不定値**（ゴミデータ）が入っています。

```c
// 100バイトのメモリを確保
char *ptr = (char *)malloc(100);
if (ptr == NULL) {
    // メモリ確保失敗時のエラーハンドリング
    return -1;
}
```

#### 2. `calloc` (Clear Allocation)
要素数と1要素あたりのサイズを指定して確保します。`malloc` と異なり、確保された領域は**すべて `0` でクリア初期化**されます。

```c
// int型10個分の領域を確保し、0で初期化
int *arr = (int *)calloc(10, sizeof(int));
if (arr == NULL) {
    return -1;
}
```

#### 3. `realloc` (Re-Allocation)
すでに確保されたヒープ領域のサイズを変更（拡大・縮小）します。
元の場所の直後を拡張できない場合、別の広いアドレスへデータを全コピーした上で自動的に旧領域を解放し、新しいポインタを返します。

```c
// 既存の領域を2倍のサイズ（20個分）に拡張
int *new_arr = (int *)realloc(arr, sizeof(int) * 20);
if (new_arr == NULL) {
    // 失敗しても元の arr は解放されていないため手動で free(arr) が必要
    free(arr);
    return -1;
}
arr = new_arr;
```

#### 4. `free` (Deallocation)
`malloc` / `calloc` / `realloc` で確保したヒープ領域をOSへ返却・解放します。

```c
free(ptr);
ptr = NULL; // 安全のため解放後は必ず NULL を代入する習慣をつける
```

---

### ③ 動的配列の容量倍増（Amortized O(1)）アルゴリズム

固定長の配列では、ファイル数や要素数が事前予測できない場合に要素あふれを起こします。
これを解決するのが**動的配列（Dynamic Array）**です。

```
[初期状態: capacity = 4, count = 4]
+----+----+----+----+
| F1 | F2 | F3 | F4 |   (満杯！)
+----+----+----+----+

[要素追加時: realloc で capacity を 2倍 (8) に拡張]
+----+----+----+----+----+----+----+----+
| F1 | F2 | F3 | F4 | F5 |    |    |    |
+----+----+----+----+----+----+----+----+
                     ^
               count = 5, capacity = 8
```

1要素追加ごとに `realloc` で +1 サイズ拡大すると、データの全コピーが毎回発生して計算量が $O(N^2)$ に悪化します。
しかし**容量を2倍ずつ拡張**することで、コピーコストが均等化され、1要素あたりの追加コストはならし計算量（Amortized Time Complexity）で **$O(1)$** となり、非常に効率的になります。

---

## 2. 現場で飛び交う業界用語辞典

- **メモリリーク (Memory Leak)**:
  `malloc` 等で確保したヒープ領域を `free` せずに放置し、アクセス不能なままメモリ消費が増え続ける現象。サーバーや常駐プログラムでは最終的にメモリ枯渇でクラッシュを引き起こす。
- **ダングリングポインタ (Dangling Pointer / ぶら下がりポインタ)**:
  `free()` で解放済みのメモリ領域を指し続けたままのポインタ。解放後に誤ってアクセスすると、未定義動作（データの破損やセグメンテーション違反）の原因となる。
- **二重解放 (Double Free)**:
  同じメモリ領域に対して2回 `free()` を呼び出すバグ。ヒープの管理情報が破壊され、セキュリティ脆弱性（任意コード実行など）の原因となる。
- **AddressSanitizer (ASan)**:
  コンパイル時に `-fsanitize=address` オプションを付与することで、実行時にメモリリークや境界外アクセス、Double Free 等を即座に検知・レポートしてくれる開発用ツール。

### 構造体定義 (`gear/include/file_list.h`)

```c
typedef struct {
    char *filename;     // 動的確保したファイル名文字列へのポインタ
    char extension[32]; // 固定長拡張子バッファ (例: "c", "txt")
    size_t size_bytes;  // ファイルサイズ
} FileItem;

typedef struct {
    FileItem *items;    // FileItem の動的配列ポインタ
    size_t count;       // 現在格納されている要素数
    size_t capacity;    // 現在確保されている最大容量
} FileList;
```

---

### 実装すべき3つの関数仕様

#### 1. `int init_file_list(FileList *list, size_t initial_capacity)`
- **説明**: `FileList` 構造体を初期化し、指定された初期容量 `initial_capacity` 分の `FileItem` 配列をヒープ領域に確保する。
- **引数**:
  - `list`: 初期化対象の `FileList` ポインタ
  - `initial_capacity`: 初期確保容量
- **戻り値**: 成功時は `0`、引数不正（`list == NULL` や `initial_capacity == 0`）または `malloc` 失敗時は `-1`。
- **処理詳細**:
  - `list->items` を `malloc(sizeof(FileItem) * initial_capacity)` で確保。
  - `list->count = 0`
  - `list->capacity = initial_capacity`

#### 2. `int add_file_item(FileList *list, const char *filename, const char *ext, size_t size_bytes)`
- **説明**: リストに新しいファイル情報を1件追加する。容量不足時は容量を2倍に拡張する。
- **引数**:
  - `list`: 対象の `FileList` ポインタ
  - `filename`: ファイル名文字列
  - `ext`: 拡張子文字列
  - `size_bytes`: バイトサイズ
- **戻り値**: 成功時は `0`、引数不正（`list == NULL`, `list->items == NULL`, `filename == NULL`, `ext == NULL`）またはメモリ確保失敗時は `-1`。
- **処理詳細**:
  - `list->count == list->capacity` の場合、`realloc` を使って容量を `list->capacity * 2` に拡張。
  - `filename` 用のメモリを `malloc(strlen(filename) + 1)` で動的確保し、文字列をコピー。
  - `ext` を `extension[32]` バッファへ安全にコピー（末尾ヌル文字 `\0` を保証）。
  - `size_bytes` を設定し、`list->count++` を行う。

#### 3. `void free_file_list(FileList *list)`
- **説明**: `FileList` が保持しているすべてのヒープメモリを安全に解放し、初期状態にリセットする。
- **引数**:
  - `list`: 対象の `FileList` ポインタ
- **処理詳細**:
  - `list` が `NULL` の場合は即座にリターン。
  - 各要素 (`0` から `count - 1`) の `items[i].filename` をすべて `free` する。
  - `list->items` 自体を `free` する。
  - `list->items = NULL`, `list->count = 0`, `list->capacity = 0` へリセット。

#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include "file_list.h"

int main(void) {
    FileList list;
    size_t initial_cap = 4;

    if (init_file_list(&list, initial_cap) != 0) {
        fprintf(stderr, "Error: init_file_list failed\n");
        return 1;
    }

    if (list.count != 0 || list.capacity != initial_cap || list.items == NULL) {
        fprintf(stderr, "Error: Invalid initial state\n");
        free_file_list(&list);
        return 1;
    }

    const size_t total_files = 1000;
    for (size_t i = 0; i < total_files; i++) {
        char name_buf[64];
        snprintf(name_buf, sizeof(name_buf), "file_%04zu.dat", i);

        if (add_file_item(&list, name_buf, "dat", (i + 1) * 100) != 0) {
            fprintf(stderr, "Error: add_file_item failed at index %zu\n", i);
            free_file_list(&list);
            return 1;
        }
    }

    if (list.count != total_files) {
        fprintf(stderr, "Error: Expected count %zu, got %zu\n", total_files, list.count);
        free_file_list(&list);
        return 1;
    }

    if (list.capacity < total_files) {
        fprintf(stderr, "Error: Expected capacity >= %zu, got %zu\n", total_files, list.capacity);
        free_file_list(&list);
        return 1;
    }

    // Check first, middle, and last item
    if (strcmp(list.items[0].filename, "file_0000.dat") != 0 || list.items[0].size_bytes != 100) {
        fprintf(stderr, "Error: First item mismatch\n");
        free_file_list(&list);
        return 1;
    }

    if (strcmp(list.items[499].filename, "file_0499.dat") != 0 || list.items[499].size_bytes != 50000) {
        fprintf(stderr, "Error: Middle item mismatch\n");
        free_file_list(&list);
        return 1;
    }

    if (strcmp(list.items[999].filename, "file_0999.dat") != 0 || list.items[999].size_bytes != 100000) {
        fprintf(stderr, "Error: Last item mismatch\n");
        free_file_list(&list);
        return 1;
    }

    printf("Successfully added %zu files. Dynamic array capacity expanded to %zu.\n", list.count, list.capacity);

    free_file_list(&list);

    if (list.items != NULL || list.count != 0 || list.capacity != 0) {
        fprintf(stderr, "Error: List state not properly reset after free_file_list\n");
        return 1;
    }

    return 0;
}

#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <dirent.h>
#include <sys/stat.h>

/* Helper function to determine category based on file extension */
static const char *get_category(const char *filename) {
    const char *ext = strrchr(filename, '.');
    if (ext == NULL || ext == filename) {
        return "Others";
    }

    if (strcmp(ext, ".png") == 0 || strcmp(ext, ".jpg") == 0) {
        return "Images";
    } else if (strcmp(ext, ".pdf") == 0 || strcmp(ext, ".txt") == 0) {
        return "Docs";
    } else if (strcmp(ext, ".c") == 0 || strcmp(ext, ".h") == 0) {
        return "Code";
    } else if (strcmp(ext, ".zip") == 0) {
        return "Archives";
    } else {
        return "Others";
    }
}

int clean_directory(const char *target_dir, int dry_run) {
    if (target_dir == NULL) {
        return -1;
    }

    DIR *dir = opendir(target_dir);
    if (dir == NULL) {
        perror("opendir failed");
        return -1;
    }

    struct dirent *entry;
    int moved_count = 0;

    while ((entry = readdir(dir)) != NULL) {
        // Skip hidden files starting with '.' (including '.' and '..')
        if (entry->d_name[0] == '.') {
            continue;
        }

        // Build full path to the file
        char old_path[1024];
        snprintf(old_path, sizeof(old_path), "%s/%s", target_dir, entry->d_name);

        // Get file info using stat
        struct stat st;
        if (stat(old_path, &st) != 0) {
            continue;
        }

        // Skip subdirectories
        if (S_ISDIR(st.st_mode)) {
            continue;
        }

        // Determine category folder name
        const char *category = get_category(entry->d_name);

        // Build target subdirectory path and new file path
        char dest_dir[1024];
        char new_path[1024];
        snprintf(dest_dir, sizeof(dest_dir), "%s/%s", target_dir, category);
        snprintf(new_path, sizeof(new_path), "%s/%s/%s", target_dir, category, entry->d_name);

        if (dry_run == 0) {
            // Create target directory if it doesn't exist
            mkdir(dest_dir, 0755);

            // Move file using rename
            if (rename(old_path, new_path) == 0) {
                moved_count++;
            }
        } else {
            // Dry run mode: just count
            moved_count++;
        }
    }

    closedir(dir);
    return moved_count;
}

### ① ファイル入出力の基本（`fopen`, `fprintf`, `fclose`）

```c
#include <stdio.h>

int main(void) {
```

### ② ディレクトリの走査（`<dirent.h>`: `opendir`, `readdir`, `closedir`）

フォルダ（ディレクトリ）の中身を順に読み出すには、POSIXヘッダ `<dirent.h>` の関数群を使用します。

```c
#include <stdio.h>
#include <dirent.h>

void list_files(const char *dir_path) {
    DIR *dir = opendir(dir_path);
    if (dir == NULL) {
        perror("opendir failed");
        return;
    }

    struct dirent *entry;
    // readdir はディレクトリ内の要素を1つずつ返す。末尾に達すると NULL になる
    while ((entry = readdir(dir)) != NULL) {
        // entry->d_name にファイル名/フォルダ名が入っている
        printf("Found: %s\n", entry->d_name);
    }

    closedir(dir);
}
```

> 💡 **重要ルール**: `readdir` はカレントディレクトリを表す `.` や親ディレクトリを表す `..` も返します。隠しファイル（先頭が `.` のファイル）をスキップしたい場合は、`entry->d_name[0] == '.'` の条件判定で除外します。

## 2. 現場で飛び交う業界用語辞典

- **ファイルディスクリプタ（File Descriptor / FD）**:
  OSが管理する「開かれたファイルやソケット」を識別するための非負の整数値。0は標準入力（`stdin`）、1は標準出力（`stdout`）、2は標準エラー出力（`stderr`）に割り当てられており、`fopen` などで扱われる `FILE*` 構造体内部でも低レイヤのFDが保持されている。

- **サンドボックス（Sandbox / 砂場）**:
  本番のデータやOSシステム全体に影響を与えないよう、隔離された実験用の領域（フォルダや環境）。本課題の `./dungeon_box/` は、ファイル整理機能を安心してテストするためのサンドボックス領域である。

#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <errno.h>
#include <sys/stat.h>

int main(int argc, char *argv[]) {
    // 1. コマンドライン引数チェック
    if (argc < 2) {
        fprintf(stderr, "[USAGE ERROR] File path required\n");
        return 1;
    }

    const char *filepath = argv[1];
    struct stat st;

    // 2. ディレクトリ判定 (stat & S_ISDIR)
    if (stat(filepath, &st) == 0 && S_ISDIR(st.st_mode)) {
        fprintf(stderr, "[IO ERROR] Target is a directory\n");
        return 2;
    }

    // 3. ファイルオープン & エラー判定 (fopen & strerror(errno))
    FILE *fp = fopen(filepath, "r");
    if (fp == NULL) {
        fprintf(stderr, "[IO ERROR] %s\n", strerror(errno));
        return 2;
    }

    // 4. 行数カウント
    long lines = 0;
    int ch;
    while ((ch = fgetc(fp)) != EOF) {
        if (ch == '\n') {
            lines++;
        }
    }

    fclose(fp);

    // stdout に結果を出力
    printf("LINES: %ld\n", lines);
    return 0;
}

## 1. この階層で学ぶC言語とUNIX哲学の核心

### ① なぜ標準出力（`stdout`）と標準エラー出力（`stderr`）を分離するのか？
UNIXシステムには、プロセスが標準で持つ3つのI/Oストリームが存在します。

| ストリーム名 | ファイル記述子 | C言語でのストリーム | 用途 |
| :--- | :--- | :--- | :--- |
| 標準入力 (`stdin`) | `0` | `stdin` | キーボードやパイプからのデータ入力 |
| 標準出力 (`stdout`) | `1` | `stdout` | プログラムの正常な実行結果・データの出力 |
| 標準エラー出力 (`stderr`) | `2` | `stderr` | エラーメッセージ、警告、ログの出力 |

#### 分離する最大の理由：パイプライン処理の保護
UNIX思想の根本には「1つのプログラムには1つのことを上手くやらせよ（Do One Thing and Do It Well）」という原則があります。複数のプログラムをパイプ（`|`）で繋ぐ際、`stdout` のみが次のプログラムへ受け渡されます。

もしエラーメッセージを `stdout` に出力してしまうと、後続のプログラムがエラー文字列を正常なデータと誤認して処理を開始し、システム全体に二次災害を引き起こしてしまいます。エラーメッセージを `stderr` に出力することで、パイプラインのデータを汚染せずにエラーを通知できます。

```text
[正常なデータ流路]
./floor_runner data.txt | grep "TARGET" -> (stdoutのみがパイプに渡る)

[stderr分離時]
./floor_runner invalid.txt 2> error.log | grep "TARGET"
-> stdoutはパイプへ、stderrはerror.logへ分離保存される
```

---

### ② `<errno.h>` と `strerror(errno)` / `perror`
C言語の標準ライブラリ関数（`fopen` や `stat` など）が失敗した際、システムはグローバル変数 `errno` にエラー番号（整数）をセットします。

- **`errno`**: 直前に実行されたシステムコール/標準ライブラリのエラー番号（例: `ENOENT` = 2, `EACCES` = 13）。
- **`strerror(errno)`**: エラー番号に対応する人間が読める文字列メッセージ（例: `"No such file or directory"`, `"Permission denied"`）を返す関数（`<string.h>` に定義）。
- **`fprintf(stderr, ...)`**: `stderr` に対して書式設定付きで出力する関数。

```c
#include <stdio.h>
#include <string.h>
#include <errno.h>

FILE *fp = fopen("missing.txt", "r");
if (fp == NULL) {
    // stderrにエラーメッセージを出力
    fprintf(stderr, "[IO ERROR] %s\n", strerror(errno));
    return 2;
}
```

---

### ③ 終了ステータス規約（Exit Status）
プロセスが終了するとき、OSに返却する数値（`0`〜`255`）を終了ステータス（Exit Status / Return Code）と呼びます。シェルスクリプトや後続プロセスは `$?` を参照して結果を判定します。

| 終了コード | 意味 | 本階層での割り当て |
| :--- | :--- | :--- |
| `0` | 成功（SUCCESS） | ファイル読み込み＆行数カウント成功 |
| `1` | 汎用エラー / 引数エラー（USAGE ERROR） | コマンドライン引数が足りない場合 |
| `2` | I/O・環境エラー（IO ERROR） | ファイル非存在、権限不足、ディレクトリ指定など |

---

### ④ UNIXパイプラインとリダイレクト
シェルコマンドにおける出力の制御記号をマスターしましょう。

- `>` : `stdout` をファイルへ上書き保存（例: `./app > out.txt`）
- `2>` : `stderr` をファイルへ上書き保存（例: `./app 2> err.txt`）
- `2>&1` : `stderr` を `stdout` と同じ出力先に統合
- `|` : 前のコマンドの `stdout` を次のコマンドの `stdin` に流し込む

int main(void) {
    struct utsname uts;
    if (uname(&uts) != 0) {
        return 1;

    if (statvfs(".", &stat) != 0) {
        return 1;
    }

    double storage_used = 0.0;
    if (stat.f_blocks > 0) {

        double free_bytes  = (double)stat.f_bavail * (double)stat.f_frsize;

### ① `<sys/utsname.h>` : システム情報の取得 `uname()`

OSの名前、ノード名、カーネルバージョン、ハードウェアアーキテクチャなどの低レイヤ情報を取得するには、`<sys/utsname.h>` に定義された `uname()` 関数を使用します。

#### 構造体 `struct utsname` の主要メンバー

```c
#include <sys/utsname.h>

struct utsname uts;
if (uname(&uts) == 0) {
    printf("OS Name : %s\n", uts.sysname);  // 例: Linux, Darwin
    printf("Node    : %s\n", uts.nodename); // ホスト名
    printf("Release : %s\n", uts.release);  // カーネルリリース
    printf("Machine : %s\n", uts.machine);  // 例: x86_64, aarch64
}
```

- **`sysname`**: オペレーティングシステムの名前（Linux, Darwin など）。
- **`machine`**: CPUアーキテクチャ識別子（`x86_64`, `aarch64` など）。

---

### ② `<sys/statvfs.h>` : ストレージ統計の取得 `statvfs()`

ディスクやファイルシステムの総容量・使用率を正確に算出するため、`<sys/statvfs.h>` の `statvfs()` を使用します。

```c
#include <sys/statvfs.h>

struct statvfs stat;
if (statvfs(".", &stat) == 0) {
    // 総ブロック数 × ブロックサイズ ＝ 総バイト数
    unsigned long long total_bytes = (unsigned long long)stat.f_blocks * stat.f_frsize;

    // 利用可能ブロック数 × ブロックサイズ ＝ 空きバイト数
    unsigned long long free_bytes  = (unsigned long long)stat.f_bavail * stat.f_frsize;

    // 使用済みバイト数
    unsigned long long used_bytes  = total_bytes - free_bytes;

    // 使用率（パーセンテージ）の計算
    double storage_used = ((double)used_bytes / (double)total_bytes) * 100.0;

    printf("Storage Used: %.1f%%\n", storage_used);
}
```

#### 重要ポイント：
- **`stat.f_blocks`**: ファイルシステムの総ブロック数。
- **`stat.f_bavail`**: 一般ユーザーが利用可能な空きブロック数。
- **`stat.f_frsize`**: 基礎ブロックサイズ（バイト）。
- ゼロ除算（`total_bytes == 0`）を防止するため、計算前に必ずチェックまたは防御コードを入れます。

### ③ リリース最適化コンパイル（`-O2` オプション）

開発段階（デバッグ時）では `-g` や `-O0` を指定してコンパイルしますが、本番環境（プロダクション）へデプロイするバイナリでは GCC/Clang の最適化フラグ **`-O2`** を使用します。

```bash
gcc -std=c11 -O2 -Wall -Wextra -Werror -o floor_runner main.c
```

- **`-O2`（Level 2 Optimization）**:
  コードサイズを過剰に膨らませることなく、ループ展開、インライン化、レジスタ割り当ての最適化など、最高クラスの実行速度パフォーマンスを引き出す標準的な最適化レベルです。

### ④ 環境変数 `PATH` と `~/.local/bin` へのデプロイ

作成したプログラムをターミナルのどこからでもコマンド名ひとつで呼び出せるようにすることを「デプロイ（Deploy）」と呼びます。

## 2. 現場で飛び交う業界用語辞典

- **POSIX (Portable Operating System Interface)**:
  UNIX系OS（Linux, macOS, BSDなど）間でプログラムの互換性を保つための標準規格。`uname()` や `statvfs()` は POSIX 準拠のシステムコールである。
- **システムコール (System Call)**:
  ユーザープログラムがOSのカーネル機能（ファイル操作、メモリ確保、ハードウェアアクセス）を呼び出すための特殊な命令。
- **デプロイ (Deployment)**:
  開発・ビルドしたソフトウェアを実行環境に配置し、エンドユーザーが利用可能な状態にすること。
- **インライン展開 (Function Inlining)**:
  コンパイラの最適化機能（`-O2`など）の一つ。関数呼び出しのオーバーヘッドを無くすため、関数の中身を実行場所に直接埋め込む手法。
- **バイナリストリッピング (Strip)**:
  コンパイルされた実行ファイルからデバッグ用シンボル情報を削ぎ落とし、ファイルサイズを最小化する工程。

```
       [ Logic (論理・構文) ]
                /\
               /  \
              /    \
             /  SAO \
            / Kernel \
           /__________\
[ Memory (メモリ) ]  [ Audit (監査・堅牢性) ]
```

| ステータス | 意味・育成要素 | 本教材における具体例 |

## 🛠️ 完全初心者向け環境構築マニュアル

開発環境として **Linux（Ubuntu）** または **Mac (macOS)** を使用します。Windows環境の方は WSL2（Windows Subsystem for Linux）を利用して Ubuntu を構築します。

### 🪟 Windowsユーザー向け手順

#### Step 1: WSL2 (Ubuntu) のインストール
1. スタートメニューを右クリックし、「**PowerShell**（または ターミナル）」を**管理者として実行**します。
2. 以下のコマンドを実行します。
   ```powershell
   wsl --install
   ```
3. 処理が完了したら、**PCを再起動**します。
4. 再起動後、自動的に Ubuntu の初期設定画面（ユーザー名とパスワードの設定）が立ち上がります。画面の指示に従って任意のユーザー名とパスワードを設定してください。

#### Step 2: 必要な開発ツールのインストール
1. Ubuntu のターミナル（黒い画面）を開きます。
2. 以下のコマンドを実行して、C言語コンパイラ（`gcc`）やビルドツール（`make`）、デバッガ（`gdb`）、`git` を一括インストールします。
   ```bash
   sudo apt update && sudo apt install -y build-essential git gdb
   ```
   ※ パスワードを求められたら、Step 1で設定したUbuntuのパスワードを入力してください（入力中の文字は画面に表示されません）。

#### Step 3: Antigravity から WSL2 を開く手順
1. エディタ **Antigravity** を起動します。
2. キーボードで `Ctrl + Shift + P` を押し、コマンドパレットを開きます。
3. `WSL: Connect to WSL` (または `WSL: WSLへ接続`) を検索して選択します。
4. Antigravity 内のターミナルを開き（`Ctrl + @` または 上部メニュー `Terminal` ➔ `New Terminal`）、ターミナル種別で `Ubuntu (WSL)` が選択されていることを確認します。

### 🍎 Macユーザー向け手順

1. Macの「**ターミナル**」（Terminal.app）を起動します（`Cmd + Space` で SpotLight を開き「ターミナル」と検索）。
2. 以下のコマンドを実行して、Apple Command Line Tools（`gcc` / `make` / `git` 等）をインストールします。

## 💡 各階層のつまずきポイントと声かけ例

### 🏰 Floor 01: 転移門広場 (`printf`, フォーマット指定子, 型)
- **絶対につまずくポイント**:
  - `%` 自体を文字表示するためのエスケープ `%%` の失念。
  - ゼロ埋め `%04d` や小数制御 `%.1f` のフォーマットミス。
  - 末尾の改行文字 `\n` やスペース不足による `./test.sh` 差分エラー。
- **メンターの声かけ例**:
  > 💬 「出力結果が少しズレているみたいだね。ターミナルの出力と `MISSION.md` の期待値を1文字ずつ見比べてみよう！ `%` という記号そのものを表示したい時はどう書けばよかったかな？」

---

### 🏰 Floor 02: 迷宮区 (`if-else`, `argc`/`argv`, `strcmp`)
- **絶対につまずくポイント**:
  - `strcmp(s1, s2)` は「一致したときに **0** を返す」という逆直感仕様への惑わされ (`if (strcmp(...) == 0)` にすべきところを `if (strcmp(...))` と書いてしまう)。
  - `argv[1]` にアクセスする際に `argc < 2` チェックを行わずセグメンテーション違反。
- **メンターの声かけ例**:
  > 💬 「`strcmp` は文字列が『同じ』とき、どんな数値を返すかな？ 0 は C言語では偽（false）扱いになるから、`== 0` と書く必要があるんだ。引数が渡されなかった時の対策も入れてみよう！」

---

### 🏰 Floor 03: 銀の牢獄 (配列, 終端文字 `\0`, `safe_str_copy`)
- **絶対につメインつくポイント**:
  - 配列の末尾に終端文字 `\0` (NULL文字) を付け忘れる。
  - バッファサイズ `dest_size` 以上の文字をコピーして領域破壊を起こす。
- **メンターの声かけ例**:
  > 💬 「C言語の文字列はどこが終わりか、コンピュータはどうやって判断しているかな？ そう、`\0` だね！コピーした最後の位置に自分で `\0` をセットしたか確認してみよう」

---

### 🏰 Floor 04: 起草室 (関数分割, ヘッダ `.h`, インクルードガード)
- **絶対につまずくポイント**:
  - ヘッダファイルでのインクルードガード (`#ifndef ... #define ... #endif`) の記述ミス。
  - 関数宣言（プロトタイプ宣言）と関数定義の引数型不一致。
- **メンターの声かけ例**:
  > 💬 「ヘッダファイルが複数回読み込まれると『二重定義エラー』が起きるんだ。それを防ぐためのおまじない（インクルードガード）が正しく閉じられているか確認してみよう！」

---

### 🏰 Floor 05: 奈落 (ポインタ `*` `/` `&`, アドレス渡し, NULLガード)
- **絶対につまずくポイント**:
  - `*`（値の参照・間接参照）と `&`（アドレスの取得）の混乱。
  - ポインタ引数に対する `NULL` チェック漏れによるクラッシュ。
- **メンターの声かけ例**:
  > 💬 「変数の『値』そのものを渡したいのかな？それとも『変数の住所（アドレス）』を渡したいのかな？ `&` はポストに書かれた住所、`*` はその住所の家の中に入って中身を取り出す鍵だとイメージしてみよう！」

---

### 🏰 Floor 06: 魂の設計図 (`struct`, `typedef`, `enum`, アロー演算子 `->`)
- **絶対につまずくポイント**:
  - 構造体変数へのドット演算子 `.` と、構造体ポインタへのアロー演算子 `->` の混同。
  - `typedef` の構文ミス。
- **メンターの声かけ例**:
  > 💬 「今操作しようとしている変数は構造体の『実体』かな、それとも『ポインタ』かな？ ポインタ経由でメンバにアクセスするときは矢印（`->`）を使うんだったね！」

---

### 🏰 Floor 07: 断頭台 (動的メモリ確保 `malloc`, `realloc`, `free`)
- **絶対につまずくポイント**:
  - `malloc` 後にメモリ確保失敗時の `NULL` チェックを怠る。
  - `free` の呼び忘れによるメモリリーク（Memory Leak）。
- **メンターの声かけ例**:
  > 💬 「`malloc` はOSにメモリをおねだりする関数だけど、メモリが一杯だったら `NULL` が返ってくるよ。受け取った直後に `NULL` チェックが入っているか、使い終わったら `free` しているかチェックしよう！」

---

### 🏰 Floor 08: 外郭回廊 (ファイルI/O `fopen`, `readdir`, `rename`)
- **絶対につまずくポイント**:
  - `fopen` で開いたファイルの `fclose` 忘れ。
  - ディレクトリ走査（`readdir`）でドットファイル（`.` や `..`）を意図せず処理対象にしてしまう。
- **メンターの声かけ例**:
  > 💬 「ファイルやディレクトリを操作するときは、必ず開いたら閉じる（`fclose` / `closedir`）が鉄則だよ。あと、`readdir` で取得できる `.` や `..` はスキップしているかな？」

---

### 🏰 Floor 09: 鉄壁 (エラー処理 `stderr`, `errno`, `perror`)
- **絶対につまずくポイント**:
  - エラーメッセージを `printf`（標準出力）に出力してしまう（標準エラー出力 `fprintf(stderr, ...)` が正解）。
  - エラー発生時に適切な非ゼロの終了ステータスコード（例: `EXIT_FAILURE` または `1`）を返していない。
- **メンターの声かけ例**:
  > 💬 「正常な出力とエラーログは出力先を分けるのがプロの作法なんだ。`printf` ではなく `fprintf(stderr, ...)` や `perror` を使えているか確認してみよう！」

---

### 🏰 Floor 10: 紅玉宮 (全モジュール統合ビルド `-O2`, PATH登録)
- **絶対につメインつくポイント**:
  - 過去フロアで作った `.c` / `.h` モジュールの依存関係が原因の未定義シンボル（Undefined reference）エラー。
  - コンパイルオプション `-O2` や `-Werror` による潜在的な警告の検出。
- **メンターの声かけ例**:
  > 💬 「ついに最後のフロアだね！ビルドエラーが出たらログの最初の一行を読もう。どの関数が見つからないと言われているかな？過去のフロアで作成したヘッダファイルとソースコードのリンクを確認しよう！」

#include "config.h"
#include "safe_str.h"
#include <string.h>
#include <stdio.h>

int parse_args(int argc, char *argv[], GearConfig *out_config) {
    if (!out_config) {
        return -1;
    }

    memset(out_config, 0, sizeof(GearConfig));
    out_config->command = CMD_NONE;

    if (argc <= 1) {
        out_config->command = CMD_HELP;
        return 0;
    }

    int i = 1;
    while (i < argc) {
        const char *arg = argv[i];

        if (strcmp(arg, "-h") == 0 || strcmp(arg, "--help") == 0) {
            out_config->command = CMD_HELP;
            return 0;
        } else if (strcmp(arg, "-v") == 0 || strcmp(arg, "--version") == 0) {
            out_config->command = CMD_VERSION;
            return 0;
        } else if (strcmp(arg, "--dry-run") == 0) {
            out_config->dry_run = true;
        } else if (strcmp(arg, "--verbose") == 0 || strcmp(arg, "-v") == 0) {
            out_config->verbose = true;
        } else if (strcmp(arg, "stat") == 0) {
            if (out_config->command == CMD_NONE) {
                out_config->command = CMD_STAT;
            }
        } else if (strcmp(arg, "memo") == 0) {
            if (out_config->command == CMD_NONE) {
                out_config->command = CMD_MEMO;
            }
            if (i + 1 < argc && argv[i + 1][0] != '-') {
                i++;
                if (safe_str_copy(out_config->memo_text, sizeof(out_config->memo_text), argv[i]) != 0) {
                    fprintf(stderr, "Error: Memo text too long.\n");
                    return -1;
                }
            } else if (out_config->memo_text[0] == '\0') {
                fprintf(stderr, "Error: 'memo' command requires a message.\n");
                return -1;
            }
        } else if (strcmp(arg, "clean") == 0) {
            if (out_config->command == CMD_NONE) {
                out_config->command = CMD_CLEAN;
            }
        } else {
            if (out_config->command == CMD_CLEAN && out_config->target_path[0] == '\0' && arg[0] != '-') {
                if (safe_str_copy(out_config->target_path, sizeof(out_config->target_path), arg) != 0) {
                    fprintf(stderr, "Error: Target path too long.\n");
                    return -1;
                }
            } else if (out_config->command == CMD_NONE && arg[0] != '-') {
                fprintf(stderr, "Error: Unknown command or argument '%s'\n", arg);
                return -1;
            }
        }
        i++;
    }

    if (out_config->command == CMD_CLEAN && out_config->target_path[0] == '\0') {
        if (safe_str_copy(out_config->target_path, sizeof(out_config->target_path), "./dungeon_box") != 0) {
            return -1;
        }
    }

    if (out_config->command == CMD_MEMO && out_config->memo_text[0] == '\0') {
        fprintf(stderr, "Error: 'memo' command requires a message.\n");
        return -1;
    }

    return 0;
}

#include "gear.h"
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <strings.h>
#include <dirent.h>
#include <sys/stat.h>
#include <unistd.h>
#include <errno.h>

static const char *get_category(const char *ext) {
    if (!ext || ext[0] == '\0') {
        return "Others";
    }

    if (strcasecmp(ext, ".png") == 0 || strcasecmp(ext, ".jpg") == 0 ||
        strcasecmp(ext, ".jpeg") == 0 || strcasecmp(ext, ".gif") == 0) {
        return "Images";
    }

    if (strcasecmp(ext, ".pdf") == 0 || strcasecmp(ext, ".md") == 0 ||
        strcasecmp(ext, ".txt") == 0) {
        return "Docs";
    }

    if (strcasecmp(ext, ".c") == 0 || strcasecmp(ext, ".h") == 0 ||
        strcasecmp(ext, ".sh") == 0 || strcasecmp(ext, ".py") == 0) {
        return "Code";
    }

    if (strcasecmp(ext, ".zip") == 0 || strcasecmp(ext, ".tar") == 0 ||
        strcasecmp(ext, ".gz") == 0 || strcasecmp(ext, ".tgz") == 0) {
        return "Archives";
    }

    return "Others";
}

int cmd_clean_run(const GearConfig *config) {
    if (!config) {
        return 1;
    }

    DIR *dir = opendir(config->target_path);
    if (!dir) {
        fprintf(stderr, "Error: Cannot open directory '%s': %s\n", config->target_path, strerror(errno));
        return 1;
    }

    FileList flist;
    if (init_file_list(&flist, 16) != 0) {
        closedir(dir);
        fprintf(stderr, "Error: Failed to initialize file list\n");
        return 1;
    }

    struct dirent *entry;
    while ((entry = readdir(dir)) != NULL) {
        if (strcmp(entry->d_name, ".") == 0 || strcmp(entry->d_name, "..") == 0) {
            continue;
        }

        char full_path[MAX_PATH_LEN];
        if (safe_path_join(full_path, sizeof(full_path), config->target_path, entry->d_name) != 0) {
            continue;
        }

        struct stat st;
        if (stat(full_path, &st) != 0) {
            continue;
        }

        if (S_ISREG(st.st_mode)) {
            const char *dot = strrchr(entry->d_name, '.');
            const char *ext = dot ? dot : "";
            add_file_item(&flist, entry->d_name, ext, (size_t)st.st_size);
        }
    }
    closedir(dir);

    if (flist.count == 0) {
        if (config->verbose) {
            printf("No regular files to organize in '%s'.\n", config->target_path);
        }
        free_file_list(&flist);
        return 0;
    }

    for (size_t i = 0; i < flist.count; i++) {
        const char *fname = flist.items[i].filename;
        const char *ext = flist.items[i].extension;
        const char *cat = get_category(ext);

        char sub_dir[MAX_PATH_LEN];
        if (safe_path_join(sub_dir, sizeof(sub_dir), config->target_path, cat) != 0) {
            fprintf(stderr, "Error creating path for directory '%s'\n", cat);
            continue;
        }

        if (!config->dry_run) {
            struct stat st_dir;
            if (stat(sub_dir, &st_dir) != 0) {
                if (mkdir(sub_dir, 0755) != 0 && errno != EEXIST) {
                    fprintf(stderr, "Error creating directory '%s': %s\n", sub_dir, strerror(errno));
                    continue;
                }
            }
        }

        char src_path[MAX_PATH_LEN];
        char dst_path[MAX_PATH_LEN];
        if (safe_path_join(src_path, sizeof(src_path), config->target_path, fname) != 0 ||
            safe_path_join(dst_path, sizeof(dst_path), sub_dir, fname) != 0) {
            fprintf(stderr, "Error constructing path for '%s'\n", fname);
            continue;
        }

        if (config->dry_run) {
            printf("[DRY-RUN] Move '%s' -> '%s/'\n", fname, cat);
        } else {
            if (rename(src_path, dst_path) != 0) {
                fprintf(stderr, "Error moving '%s' -> '%s/': %s\n", fname, cat, strerror(errno));
            } else if (config->verbose) {
                printf("[MOVED] '%s' -> '%s/'\n", fname, cat);
            }
        }
    }

    free_file_list(&flist);
    return 0;
}

#define _POSIX_C_SOURCE 200809L
#include "gear.h"
#include <stdio.h>
#include <stdlib.h>
#include <time.h>

int cmd_memo_run(const GearConfig *config) {
    if (!config) {
        return 1;
    }

    const char *memo_path = getenv("GEAR_MEMO_PATH");
    if (!memo_path || memo_path[0] == '\0') {
        memo_path = "./.gear_memo.log";
    }

    FILE *fp = fopen(memo_path, "a");
    if (!fp) {
        perror("Error opening memo log file");
        return 1;
    }

    struct timespec ts;
    clock_gettime(CLOCK_REALTIME, &ts);

    struct tm tm_buf;
    localtime_r(&ts.tv_sec, &tm_buf);

    int ms = (int)(ts.tv_nsec / 1000000);

    fprintf(fp, "[%04d-%02d-%02d %02d:%02d:%02d.%03d] %s\n",
            tm_buf.tm_year + 1900,
            tm_buf.tm_mon + 1,
            tm_buf.tm_mday,
            tm_buf.tm_hour,
            tm_buf.tm_min,
            tm_buf.tm_sec,
            ms,
            config->memo_text);

    fclose(fp);

    printf("[MEMO RECORDED] -> %s\n", memo_path);

    return 0;
}

#include "gear.h"
#include "../../shared/sao_ui.h"
#include <stdio.h>
#include <stdlib.h>
#include <sys/utsname.h>
#include <sys/statvfs.h>

int cmd_stat_run(const GearConfig *config) {
    (void)config;

    const char *user = getenv("USER");
    if (!user || user[0] == '\0') {
        user = "UNKNOWN_PLAYER";
    }

    struct utsname uts;
    if (uname(&uts) != 0) {
        perror("uname failed");
        return 1;
    }

    struct statvfs vfs;
    if (statvfs(".", &vfs) != 0) {
        perror("statvfs failed");
        return 1;
    }

    unsigned long long total_bytes = (unsigned long long)vfs.f_blocks * vfs.f_frsize;
    unsigned long long free_bytes = (unsigned long long)vfs.f_bfree * vfs.f_frsize;
    unsigned long long used_bytes = total_bytes - free_bytes;

    double used_pct = 0.0;
    if (total_bytes > 0) {
        used_pct = ((double)used_bytes / (double)total_bytes) * 100.0;
    }

    int total_blocks = 10;
    int filled_blocks = (int)((used_pct / 100.0) * total_blocks + 0.5);
    if (filled_blocks > total_blocks) filled_blocks = total_blocks;
    if (filled_blocks < 0) filled_blocks = 0;

    char bar_str[128] = {0};
    int pos = 0;
    bar_str[pos++] = '[';
    for (int i = 0; i < filled_blocks; i++) {
        /* "█" is UTF-8 bytes 0xE2, 0x96, 0x88 */
        bar_str[pos++] = (char)0xE2;
        bar_str[pos++] = (char)0x96;
        bar_str[pos++] = (char)0x88;
    }
    for (int i = filled_blocks; i < total_blocks; i++) {
        /* "░" is UTF-8 bytes 0xE2, 0x96, 0x91 */
        bar_str[pos++] = (char)0xE2;
        bar_str[pos++] = (char)0x96;
        bar_str[pos++] = (char)0x91;
    }
    bar_str[pos++] = ']';
    bar_str[pos] = '\0';

    SAO_PRINT_HEADER("PLAYER & SYSTEM STATS");
    printf(" PLAYER NAME : %s\n", user);
    printf(" OS SYSTEM   : %s %s\n", uts.sysname, uts.release);
    printf(" ARCHITECTURE: %s\n", uts.machine);
    printf(" STORAGE USAGE: %s %.1f%%\n", bar_str, used_pct);
    SAO_PRINT_FOOTER();

    return 0;
}

#include "file_list.h"
#include "safe_str.h"
#include <stdlib.h>
#include <string.h>

int init_file_list(FileList *list, size_t initial_capacity) {
    if (!list) {
        return -1;
    }
    size_t cap = (initial_capacity > 0) ? initial_capacity : 8;
    list->items = malloc(cap * sizeof(FileItem));
    if (!list->items) {
        return -1;
    }
    list->count = 0;
    list->capacity = cap;
    return 0;
}

int add_file_item(FileList *list, const char *filename, const char *ext, size_t size_bytes) {
    if (!list || !filename) {
        return -1;
    }
    if (list->count >= list->capacity) {
        size_t new_cap = (list->capacity == 0) ? 8 : list->capacity * 2;
        FileItem *new_items = realloc(list->items, new_cap * sizeof(FileItem));
        if (!new_items) {
            return -1;
        }
        list->items = new_items;
        list->capacity = new_cap;
    }

    size_t name_len = strlen(filename);
    char *dup_name = malloc(name_len + 1);
    if (!dup_name) {
        return -1;
    }
    memcpy(dup_name, filename, name_len + 1);

    list->items[list->count].filename = dup_name;
    if (safe_str_copy(list->items[list->count].extension, sizeof(list->items[list->count].extension), ext ? ext : "") != 0) {
        free(dup_name);
        return -1;
    }
    list->items[list->count].size_bytes = size_bytes;
    list->count++;

    return 0;
}

void free_file_list(FileList *list) {
    if (!list) {
        return;
    }
    if (list->items) {
        for (size_t i = 0; i < list->count; i++) {
            free(list->items[i].filename);
        }
        free(list->items);
        list->items = NULL;
    }
    list->count = 0;
    list->capacity = 0;
}

            print_help();

        case CMD_VERSION:
            print_version();
            return 0;
        case CMD_STAT:
            return cmd_stat_run(&config);
        case CMD_MEMO:
            return cmd_memo_run(&config);
        case CMD_CLEAN:

#include "safe_str.h"
#include <string.h>
#include <stdbool.h>

int safe_str_copy(char *dest, size_t dest_size, const char *src) {
    if (!dest || dest_size == 0) {
        return -1;
    }
    if (!src) {
        dest[0] = '\0';
        return 0;
    }
    size_t src_len = strlen(src);
    if (src_len >= dest_size) {
        return -1;
    }
    memcpy(dest, src, src_len + 1);
    return 0;
}

int safe_path_join(char *dest, size_t dest_size, const char *dir, const char *file) {
    if (!dest || dest_size == 0 || !dir || !file) {
        return -1;
    }
    size_t dir_len = strlen(dir);
    size_t file_len = strlen(file);
    bool needs_slash = (dir_len > 0 && dir[dir_len - 1] != '/');
    size_t total_len = dir_len + (needs_slash ? 1 : 0) + file_len;

    if (total_len >= dest_size) {
        return -1;
    }

    memcpy(dest, dir, dir_len);
    size_t pos = dir_len;
    if (needs_slash) {
        dest[pos++] = '/';
    }
    memcpy(dest + pos, file, file_len + 1);
    return 0;
}

#!/bin/bash
# SAO: Kernel - Common Test Helper Library

GREEN='\033[1;32m'
RED='\033[1;31m'
CYAN='\033[1;36m'
YELLOW='\033[1;33m'
NC='\033[0m'

USE_SOLUTION=0
if [ "$1" = "--solution" ]; then
    USE_SOLUTION=1
fi

sao_banner() {
    local floor_num="$1"
    local floor_title="$2"
    echo -e "${CYAN}==================================================${NC}"
    echo -e "${CYAN}  SWORD ART ONLINE : KERNEL - FLOOR ${floor_num} BOSS TEST${NC}"
    echo -e "${CYAN}  [${floor_title}]${NC}"
    if [ "$USE_SOLUTION" -eq 1 ]; then
        echo -e "${YELLOW}  [MODE: SOLUTION VERIFICATION (.solution)]${NC}"
    fi
    echo -e "${CYAN}==================================================${NC}"
}

sao_pass() {
    local msg="$1"
    echo -e "${GREEN}[PASS]${NC} ${msg}"
}

sao_fail() {
    local msg="$1"
    echo -e "${RED}[FAIL]${NC} ${msg}"
    echo -e "${RED}--------------------------------------------------${NC}"
    echo -e "${RED}【判定】 FAILED... ロジックを見直し、再び挑みたまえ。${NC}"
    exit 1
}

sao_complete() {
    local floor_id="$1"
    echo -e "${GREEN}--------------------------------------------------${NC}"
    echo -e "${GREEN}【判定】 CLEARED! 転移門が開かれた。次層へ進みたまえ！${NC}"
    echo -e "${GREEN}==================================================${NC}"
    if [ "$USE_SOLUTION" -eq 0 ]; then
        local root_dir
        root_dir="$(cd "$(dirname "${BASH_SOURCE[0]}")/.." && pwd)"
        echo "$(date '+%Y-%m-%d %H:%M:%S') - ${floor_id} CLEARED" >> "${root_dir}/.sao_progress"
    fi
    exit 0
}
