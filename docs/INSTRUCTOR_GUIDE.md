## 🎯 メンターの基本方針・心構え

1. **「教えすぎない」伴走型アドバイス**
   - すぐに答え（コード）を教えるのではなく、受講生自身にコードとエラーメッセージを読ませ、**質問と問いかけで思考を誘導**してください。
2. **3大ステータス（Logic / Memory / Audit）の意識付け**
   - 単に「動いたからOK」とせず、「メモリリークはないか？（Memory）」「NULLが渡されたらどうなるか？（Audit）」というプロの品質意識を促します。
3. **エラーメッセージ恐れるなかれ**
   - 初心者はコンパイルエラーやセグメンテーション違反（Segmentation Fault）を極度に恐れます。「エラーはプログラムが問題を教えてくれている親切なヒント」と捉えさせましょう。

## 💡 各階層のつまずきポイントと声かけ例

### 🏰 Floor 01: 転移門広場 (`printf`, フォーマット指定子, 型)
- **絶対につまずくポイント**:
  - `%` 自体を文字表示するためのエスケープ `%%` の失念。
  - ゼロ埋め `%04d` や小数制御 `%.1f` のフォーマットミス。
  - 末尾の改行文字 `\n` やスペース不足による `./test.sh` 差分エラー。
- **メンターの声かけ例**:
  > 💬 「出力結果が少しズレているみたいだね。ターミナルの出力と `MISSION.md` の期待値を1文字ずつ見比べてみよう！ `%` という記号そのものを表示したい時はどう書けばよかったかな？」

---

### 🏰 Floor 02: 迷宮区 (`if-else`, `argc`/`argv`, `strcmp`)
- **絶対につまずくポイント**:
  - `strcmp(s1, s2)` は「一致したときに **0** を返す」という逆直感仕様への惑わされ (`if (strcmp(...) == 0)` にすべきところを `if (strcmp(...))` と書いてしまう)。
  - `argv[1]` にアクセスする際に `argc < 2` チェックを行わずセグメンテーション違反。
- **メンターの声かけ例**:
  > 💬 「`strcmp` は文字列が『同じ』とき、どんな数値を返すかな？ 0 は C言語では偽（false）扱いになるから、`== 0` と書く必要があるんだ。引数が渡されなかった時の対策も入れてみよう！」

---

### 🏰 Floor 03: 銀の牢獄 (配列, 終端文字 `\0`, `safe_str_copy`)
- **絶対につメインつくポイント**:
  - 配列の末尾に終端文字 `\0` (NULL文字) を付け忘れる。
  - バッファサイズ `dest_size` 以上の文字をコピーして領域破壊を起こす。
- **メンターの声かけ例**:
  > 💬 「C言語の文字列はどこが終わりか、コンピュータはどうやって判断しているかな？ そう、`\0` だね！コピーした最後の位置に自分で `\0` をセットしたか確認してみよう」

---

### 🏰 Floor 04: 起草室 (関数分割, ヘッダ `.h`, インクルードガード)
- **絶対につまずくポイント**:
  - ヘッダファイルでのインクルードガード (`#ifndef ... #define ... #endif`) の記述ミス。
  - 関数宣言（プロトタイプ宣言）と関数定義の引数型不一致。
- **メンターの声かけ例**:
  > 💬 「ヘッダファイルが複数回読み込まれると『二重定義エラー』が起きるんだ。それを防ぐためのおまじない（インクルードガード）が正しく閉じられているか確認してみよう！」

---

### 🏰 Floor 05: 奈落 (ポインタ `*` `/` `&`, アドレス渡し, NULLガード)
- **絶対につまずくポイント**:
  - `*`（値の参照・間接参照）と `&`（アドレスの取得）の混乱。
  - ポインタ引数に対する `NULL` チェック漏れによるクラッシュ。
- **メンターの声かけ例**:
  > 💬 「変数の『値』そのものを渡したいのかな？それとも『変数の住所（アドレス）』を渡したいのかな？ `&` はポストに書かれた住所、`*` はその住所の家の中に入って中身を取り出す鍵だとイメージしてみよう！」

---

### 🏰 Floor 06: 魂の設計図 (`struct`, `typedef`, `enum`, アロー演算子 `->`)
- **絶対につまずくポイント**:
  - 構造体変数へのドット演算子 `.` と、構造体ポインタへのアロー演算子 `->` の混同。
  - `typedef` の構文ミス。
- **メンターの声かけ例**:
  > 💬 「今操作しようとしている変数は構造体の『実体』かな、それとも『ポインタ』かな？ ポインタ経由でメンバにアクセスするときは矢印（`->`）を使うんだったね！」

---

### 🏰 Floor 07: 断頭台 (動的メモリ確保 `malloc`, `realloc`, `free`)
- **絶対につまずくポイント**:
  - `malloc` 後にメモリ確保失敗時の `NULL` チェックを怠る。
  - `free` の呼び忘れによるメモリリーク（Memory Leak）。
- **メンターの声かけ例**:
  > 💬 「`malloc` はOSにメモリをおねだりする関数だけど、メモリが一杯だったら `NULL` が返ってくるよ。受け取った直後に `NULL` チェックが入っているか、使い終わったら `free` しているかチェックしよう！」

---

### 🏰 Floor 08: 外郭回廊 (ファイルI/O `fopen`, `readdir`, `rename`)
- **絶対につまずくポイント**:
  - `fopen` で開いたファイルの `fclose` 忘れ。
  - ディレクトリ走査（`readdir`）でドットファイル（`.` や `..`）を意図せず処理対象にしてしまう。
- **メンターの声かけ例**:
  > 💬 「ファイルやディレクトリを操作するときは、必ず開いたら閉じる（`fclose` / `closedir`）が鉄則だよ。あと、`readdir` で取得できる `.` や `..` はスキップしているかな？」

---

### 🏰 Floor 09: 鉄壁 (エラー処理 `stderr`, `errno`, `perror`)
- **絶対につまずくポイント**:
  - エラーメッセージを `printf`（標準出力）に出力してしまう（標準エラー出力 `fprintf(stderr, ...)` が正解）。
  - エラー発生時に適切な非ゼロの終了ステータスコード（例: `EXIT_FAILURE` または `1`）を返していない。
- **メンターの声かけ例**:
  > 💬 「正常な出力とエラーログは出力先を分けるのがプロの作法なんだ。`printf` ではなく `fprintf(stderr, ...)` や `perror` を使えているか確認してみよう！」

---

### 🏰 Floor 10: 紅玉宮 (全モジュール統合ビルド `-O2`, PATH登録)
- **絶対につメインつくポイント**:
  - 過去フロアで作った `.c` / `.h` モジュールの依存関係が原因の未定義シンボル（Undefined reference）エラー。
  - コンパイルオプション `-O2` や `-Werror` による潜在的な警告の検出。
- **メンターの声かけ例**:
  > 💬 「ついに最後のフロアだね！ビルドエラーが出たらログの最初の一行を読もう。どの関数が見つからないと言われているかな？過去のフロアで作成したヘッダファイルとソースコードのリンクを確認しよう！」

## 🔍 PR (Pull Request) レビュー基準・チェックリスト

受講生が課題を提出・クリアした際、メンターは以下のチェックリストに基づいてレビューを行ってください。

- [ ] **1. コンパイル判定 (Logic)**
  - `gcc -std=c11 -Wall -Wextra -Werror` で警告・エラーゼロでコンパイルできるか。
- [ ] **2. 自動テスト通過 (Logic)**
  - 該当階層の `./test.sh` を実行し、`CLEARED!` が出力されるか。
- [ ] **3. メモリ・ポインタ安全系 (Memory)**
  - ポインタを受け取るすべての関数で `NULL` ガードが行われているか。
  - `malloc` したメモリは漏れなく `free` されているか。
  - 配列アクセスや文字列コピーで境界外アクセス（バッファオーバーフロー）の危険性がないか。
- [ ] **4. エラーハンドリング・堅牢性 (Audit)**
  - システムコールやファイル操作関数（`fopen`, `malloc`, `opendir`）の戻り値チェックが行われているか。
  - エラー発生時に `stderr` への出力および適切な終了ステータスが返されているか。
- [ ] **5. コードスタイル & 可読性**
  - インデントが統一され、不必要なマジックナンバーが排除されているか。

## 🚨 緊急時・確認用コマンド（模範解答の使い方）

本教材には、メンターが受講生の詰まりを解消する際の確認用、および自動テスト用として**模範解答**が組み込まれています。

### 1. 該当階層での模範解答テスト実行
受講生の環境でテストが通らない原因が「テストスクリプト自体の問題」か「受講生のコードの実装ミス」かを切り分ける際、該当階層ディレクトリ内で以下を実行します。

```bash
cd Floor_01_Gate
./test.sh --solution
```
※ `.solution/` 配下の模範解答コードを用いてビルド・テストが実行され、`CLEARED!` となればテスト環境自体は正常であると確認できます。

### 2. 全階層の模範解答一括検証
レポジトリ全体の整合性や全フロアの解答コードを検証する場合は、ルートディレクトリから以下を実行します。

```bash
make test-solutions
```
※ 全10フロアの模範解答が一括実行され、すべてのテストが PASS することを確認できます。

### ⚠️ メンター運用ルール
- **受講生へ模範解答を直接見せるのは最終手段**としてください。
- 模範解答コード（`.solution/` 内のファイル）を見せる前に、受講生には「ヒント」や「該当箇所のドキュメントの再読」を促し、自力で解決した達成感を守るように徹底してください。
